# 代理返佣边界与账内核查

## 范围（2026-09-15）

本阶段保留代理赚差价、主站普通推广独立返佣。没有开放代理下级分佣，没有修改费率、切换收款模式、改动历史账户余额或接入生产环境。

## 本次修复

- 注册消费邀请码前锁定邀请人并复核代理下级身份。旧代理下级邀请码按无效邀请码处理：非强制邀请时不归因，强制邀请时拒绝；不消费该邀请码，不重新绑定代理。
- 下单计佣同时检查买家和邀请人。不能以普通主站买家绕过对代理下级邀请人的限制；不修改用户历史邀请关系。
- 后台佣金审核在订单锁内复核代理归属、订单与退款状态、是否已有入账流水。可疑订单不能转为发放中，管理员仍可拒绝待确认佣金。
- 发放入口自身使用事务和订单锁，检查买家、各级收款人、退款状态、资金上限及历史佣金流水。直接调用入口也不能绕过检查。
- 多级比例必须是 0 到 100 的整数且合计不超过 100。佣金预算不允许超过订单外部应付与已抵扣余额合计；这是账内金额上限，不是主站净利润证明。
- 先验证整条待分配邀请链，再修改钱包；循环、自返、代理下级收款人或数据缺失会保留订单待核查，不部分发放，不自动改成有效或清零。
- 分配金额向下取整到分，实际佣金按流水求和；余下不足一分的部分不发放。零比例层级仍正常向上遍历，不改变下一层收款人。
- 历史账本已存在时，即使佣金状态被重置，也不再次发放；中途写入失败会回滚所有收款人的金额。已入账合法收益不在此流程中追扣。
- 正常平台代收订单、无须预占的零成本自收订单不再误报为缺少经营余额预占。自收正成本预占校验仍保留。
- 现有管理端财务对账新增代理普通佣金冲突、佣金超预算、代收收益缺失、收益金额不平、收益来源异常提示。所有检测只读；当前身份与历史身份可能不同，提示不等于已经认定多发或亏损。

## 只读核查入口

更新后可在面板项目目录人工运行：

```sh
docker compose exec -T web php artisan agent:finance-audit --days=30 --json
```

- 默认扫描所有来源，而不是只扫描代理订单，因为旧邀请码可能形成主站订单。
- `--days` 范围为 1 到 365；更老记录需另行只读审计。可用 `--agent=ID` 缩小到有该代理订单上下文的记录，但不能代替全局邀请码与收款人核查。
- 返回 0：本范围内未发现已实现规则的异常；1：存在待核查项；2：参数不合法或必要表未就绪。数据库异常也不应作为通过处理。
- JSON 包含范围、总数、样本上限和异常编码，省去邮箱字段。输出仍含内部订单与用户编号，仅供有权限人员保存。
- 输出明确为 `database_only`，不验证网关实际到账或 MySQL 真并发，不可作为开放代收、退款或打款的单独依据。
- 不自动修复、不自动发佣金、不自动退款、不自动冻结账户，不注册新的定时任务。
