# 支付方式收款调度

入口：keli-admin 的「系统管理 → 支付配置」，编辑支付方式中的「收款调度」。

## 设置

- 每日收款目标：界面填写人民币元，最多两位小数；数据库保存整数分。0 表示不限。
- 达到目标后：可选择「排到未达额方式之后」或「暂停新支付」。默认后置。
- 开放时段：默认全天；可设置最多 12 个每日重复时段。结束早于开始表示跨午夜，例如 22:00 至次日 06:00。开始与结束不能相同，全天请关闭时段开关。
- 时间采用面板 `config/app.php` 的 `app.timezone`，当前默认 `Asia/Shanghai`。不依赖客户设备时间。
- 列表显示今日收款、目标和状态；悬停金额查看剩余目标，悬停状态查看时段、时区及预计恢复时间。管理员刷新列表更新统计。

平台与代理自有支付方式均按各自支付配置 ID 执行策略；本期统一由管理员配置，代理原有编辑界面不会覆盖这些设置。

## 展示顺序

先排除手动停用、非开放时段、达额暂停的方式，再按以下顺序排列：

1. 未达额方式优先于达额后置方式。
2. 同一达额状态中，处于开放时段的限时方式优先于全天方式。
3. 同组按后台手动排序，再按 ID 稳定排序。

例如 A 全天、目标 3000 元；B 每日 18:00 至 23:00、目标 5000 元：

| 情况 | 用户端顺序 |
| --- | --- |
| 18:00 前或 23:00 后 | A |
| 开放时段内，均未达额 | B、A |
| B 达额后置，A 未达额 | A、B |
| 均达额且均后置 | B、A |
| B 达额暂停 | 仅 A |

时段包含开始时刻，不包含结束时刻。跨午夜的时段不改变每日目标的统计日期。

## 统计口径

按面板确认付款的 `paid_at` 统计当地自然日 `[00:00, 次日00:00)`，金额为订单外部应付 `total_amount + handling_amount`。其中订单金额已经扣除余额、优惠等；不统计未支付、免费、全余额支付订单。

统计为人民币订单口径，包含面板手续费，不是网关扣除费率后的净结算金额。USDT 等数字货币也按该订单的原始人民币金额统计，不混加币种数量。

同一支付配置 ID 在多个站点使用时共享当日总额；不同支付配置 ID 分别统计，即使插件名称或商户相同也不合并。退款、折抵或订单后续状态变化不返还收款目标；重复回调不会重复增加累计。

每日通过时间边界自动恢复，不需要额外定时任务。暂停且配置时段的方式，要等次日第一个可用时刻恢复。

## 已有订单与边界

这是**收款调度目标，不是绝对收款上限**。已有支付链接、并发请求和晚到回调可能使实际收款超过目标；本期不做待支付额度预占，也不替代支付服务商的硬性限额。

达额暂停、非开放时段仅阻止新的支付发起，不自动修改 `enable` 或手动排序，也不限制已发起订单的正常支付回调。手动停用仍保留原有行为，不用于模拟达额暂停。

用户端进入结算、返回页面和点击付款时更新可用列表。默认选择优先的非余额方式，用户主动选择的仍可用方式保持不变。失效或费用变化时要求重新确认，不会自动向另一个网关创建订单。已经打开的二维码不因列表变化替换。

全部方式不可用时提示暂无可用支付方式，不偷偷启用暂停方式。旧用户主题即使保留旧列表，也无法绕过服务端新支付校验。

## 升级与验证

本功能需要后端迁移 `2026_09_11_000001_add_payment_collection_policy.php`，为支付方式增加可空 JSON 配置，并为订单增加 `(payment_id, paid_at)` 索引。沿用现有受保护部署流程执行迁移；大订单表首次建索引建议安排低峰并先备份。

历史方式配置为空，默认保持「不限、全天、原手动顺序」。旧后台或代理界面未提交该字段时保留现有策略。keli-admin 构建需同步进 keliboard；keli-user 新主题改善刷新和重新确认体验，后端校验不依赖主题版本。

本地测试覆盖时段边界、跨日恢复、多站汇总、退款不回补、排序优先级、旧字段兼容、服务端拒绝过期选择、晚到及重复回调。浏览器验证使用模拟接口，不创建真实支付订单。
