# 服务 123：限时执行入口与放行条件

状态：本地实现和回归，不是执行批准。本轮不连接正式面板或服务商；不接管、不部署、不建机、不改 DNS，保留 #17，不动 tanzhen。全局生产硬门禁、自动创建、自动轮换和 DNS 自动切换继续关闭。

## 入口行为

- `machines:usdo1-failover` 只接受 `start`、`status`、`stop`。它不签发授权、不接纳源机、不配置凭证、不写回退结果。没有新增 Web 入口、后台调度或通用授权开关。正式的硬门禁仍拒绝新建执行。
- 固定服务 123（ID 1）和源机 #17，要求管理员身份、已有的手动停写限时授权、当前服务修订、当前 Agent 版本和同一成员的真实故障计划。复用原生授权绑定和执行日志；已有原执行时只读返回，不能因回执丢失换计划或再派发。最多两小时是授权上限，原生任务或清理预留时间可更短。
- 停止先撤销授权，再让原生工作器作废票据并结算已请求的停止；重查只处理本执行。不自动释放写入占用，不推定在途操作失败。超时或停写只允许核对原请求和单独批准的恢复，不重投云创建或 DNS 写入。
- 本地专项回归：17 项、383 个断言通过。覆盖入口鉴权、超时、停止和陈旧票据、启动回执丢失及云创建/DNS 写入回执不明后的只读核查；没有接入真实云平台。

## 非业务节点隔离草案

目前没有现成节点组。拟建专用组 `usdo1-acceptance-only`，仅为 #17 和本轮唯一候选提供可核验的真实节点上报。另行批准后才创建逻辑节点或关联组；不移动现有节点、#8 或客户配置。

1. 测试节点拟设为 `enabled=true` 供 Agent 下发和就绪判定、`show=false` 不出现在订阅中。节点只使用专用组；组不关联任何客户套餐、普通用户或现有业务路由，不导入用户凭据。放行前分别做普通用户订阅不包含该节点、Agent 仍可收到配置且节点用户列表不含生产账号的负向核对；任何一项无法证明就停。
2. 对齐批准的 Linode 模板和 Agent 版本与二进制哈希。节点的身份、配置摘要、实际协议/端口就绪只基于 Agent 上报；这轮不做客户端握手或 HY2 转发验收，不为验收扩大外部端口暴露。
3. 只等待 #17 的真实采样达到现有连续失败阈值，不注入故障、不将缺报或未知视作失败。候选须有新鲜的连续上报和来自候选实际 IPv4 的国内可达证据；回环不能替代。候选不通过就不切 DNS，也不追加候选。
