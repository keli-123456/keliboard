# 手动故障切换

手动入口复用原生编排，只向 `redis_failover:machine_failover_operator` 投递。它不会从探测结果自动签发任务，也不会开启普通建机、自动准入、凭证轮换、候选清理重试或独立 DNS 写入入口。关闭态装配不安装或启动任何服务，也不签发授权。

## 放行前核对

- Web 与手动进程使用配套版本和共享缓存。以独立服务运行一份 `php artisan machines:work-operator-failover`，单独设置 CPU、内存和重启限制；不要加入既有 Horizon。仅该进程消费手动队列并发布短期存活凭据。后台未读到存活凭据时不接单。
- 以单独的定时器运行 `php artisan machines:advance-operator-failover`，只恢复已登记的手动任务；不要改原调度器、业务队列或 Horizon 的配置。
- `MACHINE_FAILOVER_OBSERVE_ENABLED` 只采集证据。`MACHINE_FAILOVER_OPERATOR_ENABLED` 仅允许确认后的手动任务，且要求保留传统执行开关为关闭。两个开关默认都关闭，单开任意一项不会创建机器。
- 确认源机已正式接管，服务和成员配置没有变更，有同一安装身份的连续失败证据，候选版本和 DNS 归属已核定。只读接入的源机不能走此入口。
- 仍需签发当前管理员、服务修订和 Agent 版本匹配的有效停写交接授权。按钮拥有者不能自行跳过停写证明或重用旧授权。

## 单服务交接

- 关闭态包只包含 `operator.env.closed` 和 `control.json.closed` 示例。没有真实凭证或签名钥匙。后者的 ID 为零，不能被执行。正式批准前，不安装单位文件，不生成同名可加载配置，不启动工作器或定时器。
- 审批后，把工作器及定时器装在隔离的只读版本目录，用独立的配置缓存、可写状态和日志；不使用主站的缓存、共享 Git 或原 Horizon。Web 与工作器要对齐代码、MySQL 写库和 Redis 队列/锁/心跳命名空间。独立进程不等于独占 Redis。先在 Web 入口关闭且手动队列、授权均空时验收工作器。
- 正式装配方案需指定 `MACHINE_FAILOVER_OPERATOR_FAILURE_DIRECTORY`：独立、持久、非符号链接的绝对路径，位于工作器可写的状态目录下，由工作器专用用户持有，权限 `0700`。首错保存在 `failure-state.json`，不写共享 `failed_jobs`。日志满、权限不符或另有进程持锁时停止启动；先保全证据，再另行确认处置。
- 控制 CLI 仅 Linux、本地运维用户在授权后运行，读取 root 持有、非其他用户可写的 `/etc/keliboard-failover/control.json`。它无 Web 路由，不使用环境变量作为签发后门。策略固定一个服务修订、一个源成员、一台非 #17 机器、一名管理员和一个已发布 Agent 版本；并发、尝试均必须为 1。停写与结案必须由两个不同签发身份、不同公钥签名，停写时固定两名签发方的指纹。私钥不得进入发布包或工作器。
- `machines:control-operator-failover scope` 从标准输入接收 JSON 的 `expires_at`、`evidence_sha256`，导出待签范围。最长 30 分钟，仍受原任务 20 分钟上限约束。受信核验人确认旧写入者（手工维护或 tanzhen，以实际记录为准）已持续停写，且待执行、在途和未知项均为零，再签名。不能用空队列、口头确认或测试签名替代。签名有效期最长 5 分钟。
- `issue` 在相同输入上增加 `proof`，只签发绑定该范围的一次授权，不派发任务。签发响应丢失，用 `status` 和空 JSON 对象读回有效名额。仅获授权管理员在页面确认后才登记原任务；浏览器响应丢失用原请求读回，不重新确认或换账号重发。若仍是只读接入、无连续失败证据、凭证修订或 DNS 归属变化，均不放行。

## 停止与恢复

确认仅登记一次任务。执行时重新核验交接授权和队列租约；Agent 回执还需匹配原任务、安装身份和专用回执口令。浏览器未收到响应时按原请求读取，不重发。

队列中断后仅恢复已绑定的原任务。发生异常时撤销交接授权，关闭手动入口，只停止独立进程，不使用全局 `queue:restart`、不停止 Horizon、不清任何队列。可保留独立定时器处理本地停止和结案。已经发出、结果不明的动作保留待核查，不自动改回 DNS 或删除实例。使用既有独立结案程序核对已派发动作，确认结案后才交还写权。停止不是回退。

1. 用 `revoke`（`grant_id`）先撤权，并尝试收尾该任务；若租约仍被持有，停独立工作器和正常推进定时器，待租约退出后重复 `revoke` 或运行 `machines:advance-operator-failover --stops-only`。同时关闭 Web 手动入口。已派发的外部请求不会被撤回；进程被杀不等于云端停止。
2. 任务停止且无租约后，用 `read-cloud`、`read-dns` 或 `read-dns-set` 读回原尝试（输入为 `grant_id`、`attempt_id`；记录集另需 `dns_run_id`）。手动开关关闭后仍可读回。读回不写云或 DNS、不认领候选。空列表、单次 404、超时都不能当作已清理。
3. `closure-scope` 导出当前日志范围；独立审核人逐笔核清后签名，`close` 接收 `grant_id` 和 `proof`，匹配最新日志才释放写权。已经绑定的任务不能用 `release-unused` 释放。结案不切 DNS、不删机、不自动交还权限。
4. 实际 DNS 回退必须另行批准、核对原记录和旧端可用性、恢复原值/TTL/备注并读回。版本回退与此分开：没有在途授权或未核清动作时，停止独立服务，移除本轮挂载，恢复关闭态 `bfaea83f`（本轮无资产变化）。若要再退到先前的 `560f0f8d`，按其旧资产方案另行执行。待核查时保留能读取原任务的代码或独立核查包。不回滚数据库。

独立单位文件的权限、cgroup、硬超时和中断恢复见 [Linux 验收记录](machine-failover-operator-linux-acceptance-20261128.md)。放行前仍需核对实际部署的版本、权限和凭证边界。测试签名、模拟云和 DNS 的用例不作为生产停写或已放行的证明。
