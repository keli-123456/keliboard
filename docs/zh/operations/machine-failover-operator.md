# 手动故障切换

手动入口复用原生编排，只向 `redis_failover:machine_failover_operator` 投递。它不会从探测结果自动签发任务，也不会开启普通建机、自动准入、凭证轮换、候选清理重试或独立 DNS 写入入口。

## 放行前核对

- Web 与手动进程使用配套版本和共享缓存。以独立服务运行一份 `php artisan machines:work-operator-failover`，单独设置 CPU、内存和重启限制；不要加入既有 Horizon。仅该进程消费手动队列并发布短期存活凭据。后台未读到存活凭据时不接单。
- 以单独的定时器运行 `php artisan machines:advance-operator-failover`，只恢复已登记的手动任务；不要改原调度器、业务队列或 Horizon 的配置。
- `MACHINE_FAILOVER_OBSERVE_ENABLED` 只采集证据。`MACHINE_FAILOVER_OPERATOR_ENABLED` 仅允许确认后的手动任务，且要求保留传统执行开关为关闭。两个开关默认都关闭，单开任意一项不会创建机器。
- 确认源机已正式接管，服务和成员配置没有变更，有同一安装身份的连续失败证据，候选版本和 DNS 归属已核定。只读接入的源机不能走此入口。
- 仍需签发当前管理员、服务修订和 Agent 版本匹配的有效停写交接授权。按钮拥有者不能自行跳过停写证明或重用旧授权。

## 停止与恢复

确认仅登记一次任务。执行时重新核验交接授权和队列租约；Agent 回执还需匹配原任务、安装身份和专用回执口令。浏览器未收到响应时按原请求读取，不重发。

队列中断后仅恢复已绑定的原任务。发生异常时撤销交接授权，关闭手动入口，只停止独立进程，不使用全局 `queue:restart`、不停止 Horizon、不清任何队列。可保留独立定时器处理本地停止和结案。已经发出、结果不明的动作保留待核查，不自动改回 DNS 或删除实例。使用既有独立结案程序核对已派发动作，确认结案后才交还写权。停止不是回退。
