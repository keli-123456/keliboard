# 零建机交接与回退演练

**当前仅完成本地模拟。只读预检未执行，不是实写、部署或生产接管的授权。** 不建机，不使用真实凭证、SSH、云 API、DNS 或正式数据库和队列；不改生产门禁和自动开关，不接触 tanzhen。旧执行者由测试替身模拟。

## 模拟验收

运行 `vendor/bin/phpunit tests/Unit/Services/MachineFailoverSingleARehearsalTest.php`，需要 PHP OpenSSL 和 PDO SQLite。复用[应用的停写和结案签名校验](../../../app/Services/ServerMachine/Cloud/MachineFailoverHandoverEvidence.php)，使用两套临时测试密钥。单写网关、DNS、缓存和端点健康检查均是 PHPUnit 夹具，没有正式写入入口。

2026-11-18 本地演练通过 14 项、118 条断言；连同原交接回归共通过 72 项、600 条断言。未运行真实 DNS 或生产并发验收。

| 关卡 | 模拟通过条件 |
| --- | --- |
| 旧方停写 | 先撤掉旧代数的写权，再核对待派发、在途和未核清数均为零。签名绑定本轮服务、停写标识、操作者和记录基线；签名有效但与实际观察不符也拒绝。 |
| 唯一写入路径 | SQLite 中保存代数和派发日志；旧凭据、假冒凭据、超时及同一请求重放都不会产生新写入。撤销先提交则零派发；已登记派发的单笔请求必须核清，不能补发。 |
| 结案 | 无写方时，对原意图的每笔写入核对终局回执及精确记录。只看到旧地址、超时或无回执不算未写；结案前迟到回执使旧证明失效，结案后不改原日志。 |
| 切换与回退 | 同一条 A 记录只改两次值，先到端点 B，再经独立结案和单次回退授权恢复到端点 A。ID、名称、线路、TTL、归属标记不变，其他记录零写入；回退结果未知、旧端点不健康、记录已漂移或旧地址尚未解析时不交还写权。 |

该演练不调用原生执行器，不创建或接纳候选，也不伪造原生任务回执。SQLite 本地交错和重连验证不能替代生产互斥、真实停写、权威解析及 TTL 传播的验收。

## 只读预检清单

以下输入全部**待确认**，只填非敏感信息，不发送密码、私钥或 DNS Token。对象确认前不连接远程服务；确认后也仅按批准的只读范围获取最小证据。

| 项目 | 状态 | 获准后只读核对 |
| --- | --- | --- |
| 现有隔离控制机 | 待确认 | 标识、管理地址、公钥接入与独立核实的 SSH 主机指纹；核对无生产任务、独立数据和队列、可信时钟与可审计的单写网关。没有现成合格机器就停止，不新建。 |
| 非业务端点 A / B | 均待确认 | 分别记录稳定 IPv4、预期身份和健康检查路径，确认两边无客户流量，能独立验证实际响应和回退可用性。 |
| 独立测试区与目标名称 | 待确认 | 核对权威委派、测试区归属、待用名称无同名记录或同类写任务；明确默认线路、可用 TTL、公共解析器和可接受传播时间。已有记录或不能证实隔离时换草案，不碰既有记录。 |
| DNS 凭证显示名 | 待确认 | 不读出密钥。核对所属账号、提供商、当前修订和生效权限；验证凭证与非业务测试区隔离，只有隔离网关能持有写凭证，双方执行者与核验人不能直接写。权限无法证明或范围包含生产区就停止。 |
| 操作者、停写核验人、结案复核人 | 待确认 | 核对职责独立、两套不同的可信验签公钥指纹、网关状态和任务日志读取权限，以及失败时负责人工复核的人。当前未绑定任何实际签发者。 |

**停写证据。** 由独立核验人从隔离网关、旧替身的队列及工作器核对写权已撤销、旧代数拒绝、排队/运行/待核查数都为零，并核对原记录基线。签发绑定本轮范围与停写标识的 `old_writer_stop`，证明最长五分钟有效。应验证其他脚本、凭证和自动任务不能绕过网关，不能只看面板开关或空队列。证据过期不恢复写权。

**单写与结案证据。** 交接、回退、交还各自显式批准。撤销时先提交无写方及新代数，旧请求必须被拒绝；写入意图必须先持久化，再向提供商发请求。结案复核人从独立只读通道逐笔对照派发日志和提供商终局回执或精确核对证据，绑定停写时点、日志摘要和每笔结果签发 `execution_closure`。超时、单次 404、互相矛盾或缺失的读回保留待核查，不签发结案。记录脱敏的范围、修订、代数、时间、摘要和明确的阻断原因，禁止保存密钥或原始凭证。

预检报告只标记 `通过`、`待确认` 或 `阻断`，附证据摘要与核对时间。仅有测试夹具、缺少真实停写或独占写权限证据，不能判真实预检通过。预检通过也不等于实写获批，开窗前要再次检查权限、记录和端点状态。

## 实写范围与回退草案

仅供后续另行确认。建议窗口最多两小时，最后 20 分钟只做核对、按已批准方案回退和清理，不开始新切换。使用两台现有非业务端点和现有隔离控制机，零云资源写入。不接入 tanzhen，不启用原生建机或生产调度。

1. 仅可在指定独立区新建一条全新默认线路 A，指向端点 A；记录确切 ID、名称、值、TTL 和归属。预检或开窗复核不符就停，不复用已有记录，不涉及 AAAA、TXT 或其他线路。
2. 旧替身停止写入并核清后，才授予 keliboard 测试替身单次切换权限。只按原 ID 将 A 的值改到端点 B；核对提供商精确读回、权威和约定的递归解析器，并验证实际端点响应。任何一项不明即撤销新派发，不补写。
3. 回退先撤销切换权限，核清并结案。仅当当前记录仍匹配这次写入、目的端点 A 健康时，才独立授权一次按原 ID 恢复；确认写后读回、递归传播及端点响应，再结案并显式交还旧替身写权。未确认恢复前不得交还。
4. 实写确认需包含清理权限。关停双方测试写方后，由指定人按本轮记录 ID 和归属只删除本轮新增记录；从精确查询及独立库存读回核对不存在，传播期后复核解析。不删既有资源。归属、在途或结果不明时保持停写并报告待核查，不盲目覆盖、补发或删除。
