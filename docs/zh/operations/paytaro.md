# PayTaro 渠道配置

## 管理端入口

在 keli-admin 的「支付配置」新增或编辑 PayTaro 支付方式，填写同一应用的 App ID 与 App Secret，将支付展示方式设为「站内支付弹窗」。

1. 点击「读取渠道」。未保存的新配置也可以读取，不必先启用收款。
2. 从下拉列表选择支付宝或所需数字货币渠道。列表显示渠道名称、实际收款币种及识别到的网络，选中后自动填写支付渠道 UUID。
3. 确认「已核对」显示的名称、币种、网络符合预期，再保存。每个渠道单独建立一条支付方式。

读取使用 `GET https://v3.paytaro.com/v1/app/methods`，仅访问填写密钥对应的应用。它不会创建订单、测试扣款、保存配置或开启支付方式，也不会自动选择第一项。

## UUID 不一致

下单需要的是当前应用接口 `methods[].uuid`，不是应用 UUID 或订单 UUID。若复制值不在当前应用返回列表中，管理端会提示不匹配并要求重新选择，不根据支付方式的显示名称猜测真实渠道。

「支付宝-p」等面板显示名称可以自定义，不代表网关一定使用支付宝。实际对应关系以当前应用的渠道列表为准。切换 App ID 或 App Secret 后，之前的核对结果失效，需重新读取；迟到的旧请求不会覆盖新应用的结果。

未展示或不支持的渠道会显示为不可选。应用没有渠道、认证失败、应用不匹配、超时等情况分别提示。不要发出或记录 App Secret 来排查问题。

## 兼容与边界

- 保留手动 UUID 输入。没有读取过渠道列表的旧配置仍可按原流程保存，不强制所有历史配置联网核验。
- 成功读取后，当前 UUID 不匹配或渠道不可用时，本次编辑器阻止保存；刷新查询失败不会解除已经确认的不匹配状态。
- 该核对是编辑时的状态，不保证上游渠道永久可用。用户付款仍沿用原有下单检查与支付数据校验。
- 「跳转 PayTaro 收银台」保持原行为，由收银台选择渠道，不显示站内渠道选择器。
- App Secret 只由面板后端发送给固定的 PayTaro HTTPS 接口；不跟随重定向，不把密钥、完整上游响应或传输异常回传给浏览器。管理员审计记录会脱敏密钥。
- 新增接口为 `POST /api/v2/{管理路径}/payment/getPaytaroChannels`，需要管理员身份，限流每分钟 10 次。请求字段只有 `app_id` 与 `app_secret`；不接受自定义网关地址。
- 不更改支付回调、订单金额、收款目标、开放时间段或用户主题。不需要数据库迁移；需更新 keliboard 后端及随包的 keli-admin 构建。

官方接口参考：<https://v3.paytaro.com/llms-full.txt>。

## 多链兼容范围

渠道列表动态读取，不限定支付宝和 USDT 两项。只有上游应用接口返回的渠道才会显示；未开通的渠道需要在 PayTaro 后台另行激活，面板不会自动激活或替换渠道。

站内弹窗按返回的币种、金额、地址和网络展示，覆盖以下组合的本地模拟测试：

| 币种 | 网络 |
| --- | --- |
| USDT | TRON/TRC20、BNB Smart Chain/BEP20、Polygon |
| USDC | BNB Smart Chain、Polygon、Solana |
| TRX | TRON |
| BNB | BNB Smart Chain |
| SOL | Solana |

网络解析规则：

- 兼容原有文本网络名，例如 `tron`、`BEP20`、`polygon`、`solana`。
- 支持三段式 `TRON:网络:资产`、`BSC:网络:资产`、`POLYGON:网络:资产`、`SOLANA:网络:资产`，保留明确的 MAINNET、MAINNET-BETA、DEVNET 等网络标识；第三段是资产标识，不是收款地址。
- 支持 `EVM:链ID:资产` 中的 56、97、137、80002，分别显示 BNB 主网、BNB 测试网、Polygon 主网、Polygon Amoy 测试网。`EVM:MAINNET:...` 不足以确认是哪条链，不接受；未覆盖的 ID 也不会自动映射。
- 订单未提供网络时，只读取同一应用、同一 UUID、同一币种且已展示的渠道信息。类型仍缺失时，仅接受包含 TRC20、BEP20、Polygon、Solana 的严格币种全名；不会仅凭 `USDT`、`USDC Binance`、`BNB`、`SOL` 或地址形状推断网络。
- 非空但无效的网络标识不会被其他字段覆盖。管理端与下单使用同一解析器；无法识别的渠道读取后标为不可选，旧手动配置仍会在付款时校验。
- 收款地址始终取网关订单的 `payment.data`，二维码与复制地址一致；小数金额保留完整精度，不从合约标识生成地址，也不把币种金额当成人民币订单金额。

**验证边界：** 官方公开文档仅给出部分网络类型示例；当前已有真实返回证据的是支付宝和 TRON。其他结构化标识属于兼容性测试输入，不能据此宣称所有 PayTaro 线上渠道已经实付验证。启用新渠道时先读取当前应用返回值核对；未知格式保留拒绝，核实脱敏元数据后再扩展，不跳过网络检查。此次未创建真实订单、转账或修改线上配置。

链 ID 对照依据：[BNB 官方钱包配置](https://docs.bnbchain.org/bnb-smart-chain/developers/wallet-configuration/)、[Polygon 官方网络信息](https://docs.polygon.technology/pos/reference/rpc-endpoints)。
