# 网站反代检查与订阅下发

网站监听、证书状态与公网访问检查是独立的状态。节点监听成功不代表网站可用，更不代表分站身份正确。

## 检查规则

- `website-proxy:probe` 每分钟执行，后台扫描已启用网站反代的机器。全局下发开关关闭时也可预检。
- 每个站点分别检查 HTTPS 首页和公开配置接口；必须证书有效、首页为 HTTP 200 HTML、配置接口为 HTTP 200，且 `site_context.site_id/site_code` 与目标站点一致。
- 请求只允许公网 IPv4，固定解析结果，不跟随重定向，不携带账号或令牌。每次请求限时 4 秒、响应上限 512 KiB；每轮最多 64 个目标并设扫描时间预算。
- 结果单独保存在 `v2_website_proxy_health`，不写入证书状态。超过 180 秒、检查失败、节点上报过期或路由变化的记录不能用于下发。
- 失败后需连续两次成功才恢复。订阅请求只读取检查结果，不执行网络探测。
- 主站与各分站分开选择入口；代理自有站点不继承其他站点的反代入口。

## 上线顺序

1. 节点至少更新至修复分站转发 Host 的 v0.1.375；不要把旧版 HTTP 200 当作分站身份验证通过。
2. 执行新增的健康记录表迁移，保留现有证书数据。
3. 在全局 `website_proxy_enable` 仍关闭时运行 `php artisan website-proxy:probe --machine-id=机器编号`。
4. 核对逐站检查结果、站点身份与端口，再开启全局下发。机器详情的访问验证会显示检查时间和结果。
5. 用户更新订阅后取得当前健康入口。已下载的旧订阅不会被后台主动改写；此功能不会替换订阅下载地址。

停用下发只需关闭全局 `website_proxy_enable`，不需要停机或删除证书。回退应用代码时可以保留新增健康记录表，不要对业务数据库执行破坏性降级。
