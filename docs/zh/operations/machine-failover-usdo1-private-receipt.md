## 首次回执前

- 只影响携带服务 123 启动范围的 Linode 替换任务。普通建机的安装脚本和回执入口不变。专用任务在生成初始化数据前要求明确的独立 HTTPS origin、RFC 1918 IPv4、网卡和信任方式。不齐则拒绝；任务记住传输参数指纹，同一请求不能换路由或 CA 后重用。
- 候选登记和私网建立仍由待审的前置接入完成；本实现不安装隧道或凭证。安装包装器先检查精确路由，拒绝默认路由和错误网卡；然后用不带任务令牌的 HTTPS POST 检查 TLS 和专用入口应答。只接受令牌缺失的 401。失败以 `callback_preflight`、退出码 85 留存诊断，既不跑安装，也不发送任务回执。
- 两种信任方式均验证主机名，不访问公共 DNS 来解析本轮回调。使用明确选择的系统信任，或在派发前核对 SHA-256 的公有 CA 文件；后者不加入全局信任，也不携带私钥。回调固定私网地址和接口，禁止代理及重定向。安装结束会再次核对路由，断路不会回退到公网；安装结果与回执是否到达是不同的证据。
- 原生 user-data 压缩、发送前大小上限及 Agent 安装/常驻上报地址均保留。私网和 TLS 探测通过不证明数据接口可写；生产环境的真实冷启动、证书和数据权限仍需单独验收。

## 两条数据通道

| 调用方 | 接口 | 边界 |
| --- | --- | --- |
| 独立回调 PHP-FPM | `/run/keli-usdo1/data-receipt.sock` 的 `POST /receipt` | 只提交任务、安装 ID、该任务的回执令牌和结果；不启动应用、不持有 DB/Redis 凭证。 |
| 专用工作器 | `/run/keli-usdo1/data-worker.sock` 的 `POST /tick` | 只提交空对象；服务端绑定授权和执行。可用仅加载 Composer 的 `tools/machine-acceptance/usdo1_worker_client.php`，不复用主站应用或通用队列。 |

两条 Unix 通道必须由不同 UID/组和不同短期服务令牌约束。客户端固定路径、无 TCP 回退、无重试；服务端把监听器决定的 lane、固定路径与对应令牌逐一匹配。不信任请求自报的 scope，不允许请求传入服务、授权、操作名或查询。任务回执令牌和两条通道的服务令牌是三种用途，不写入日志。

`tools/machine-acceptance/usdo1_data_broker.php` 仅为待装配的独立 FastCGI 脚本，不注册在主站路由。未来必须经各自只读配置的 Unix 监听器传入固定 `KELI_USDO1_DATA_LANE`，不能从请求头转抄，也不能作为默认 PHP 入口。代理必须自行保住端到端身份和权限，不把数据通道暴露为公网或通用数据库代理。

真实事务仍由既有服务执行，重查任务与授权、保持回执去重和撤权拒收；工作器输出仅有筛过的状态字段。现有正式执行门禁、业务通道和云/DNS 写入绑定不变。缺 Unix 监听、授权或受限数据端，一律拒绝，不能绕过到本机 DB/Redis。受信数据侧如何落地、代理的部署位置与权限、真实私网 ACL/证书仍需另审。
