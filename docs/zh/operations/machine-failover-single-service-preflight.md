## 暂停、回退与交还

1. **先叫停。** 发现双写、范围或归属漂移、连接到错误端点、写入结果不明或业务健康下降，立即撤销本服务的新派发，双方保持无写权。保留当前可用入口和原意图。不重发、清空队列、重启 Horizon 或根据超时自动回切。
2. **核清再回退。** 新方已停写并经独立结案；原端点仍健康，现有记录的 ID、归属、线路、值和 TTL 与本轮已确认写入一致，才由批准人签发一次只恢复已批准原值的回退。若已证实未切换且原基线未变，不必重写 DNS。结果不明、归属漂移或原端点不健康时保持停写，把处置交给值班负责人；不盲目覆盖或删除。仍承载业务的实例不得清理。
3. **回退后复核。** 核对提供商精确读回、权威及约定递归解析器、实际业务请求和原端点身份。回退写入也要核清并留最终回执。TTL 或递归结果不确定时不宣布恢复。发布镜像回滚与 DNS/写权回退分别批准和验证。
4. **显式交还。** 没有任何在途或未核清写入，新方及回退权限均撤销，业务稳定，原服务范围、凭证和旧方接收条件已复核，才由批准人确认交还。旧方获得新代数后才能恢复该服务，新方已不能写；结案、到期和回退完成都不会触发自动交还。
