# 服务 123：隔离执行包与待审上线范围

当前只在测试进程的 SQLite 内存库执行，云平台、DNS 和解析读回全部模拟。无生产启动器，不分发测试签名密钥，不接正式库，不部署、不建机、不改真实 DNS，不动 tanzhen。保留 #17，生产硬门禁和所有自动开关继续关闭。

## 整轮执行与保护

1. **接纳 #17**：核对 Linode 实例、创建时间、IPv4、安装身份及 Agent 发布；绑定服务 123 唯一成员和现有默认 A 的原始快照。源机接纳必须有独立签名，只登记归属，不重装、重启或改源机 DNS。接纳后重新核对服务修订和真实连续失败计划，不注入故障。
2. **限时执行**：手动停写证明验签后，限一个服务、一个原生执行、一个候选。专用工作器每次只领取这一执行的租约，不投原生故障转移或建机队列；普通工作器不消费手动接管的任务。候选初始化回调绑定这次实际派发的任务、安装 ID 和回调密钥。最多两小时，保留至少 35 分钟恢复预留；原生任务自身期限可以更短。
3. **同一条 A**：候选上报及源地址可达证据通过后，才允许给原记录写临时归属备注和切换一次 IPv4；两步只使用同一个记录 ID、默认线路和 TTL 600，不加 AAAA。写前比较精准基线和原生派发日志。DNS 已读回或结果不明时停止，不将候选提升成活动源机。创建回执丢失只重查原任务，不能创建第二台。
4. **独立回退和清理**：停止先撤权并作废工作器票据，在途或未知操作用原日志加独立读回结案。独立回退签名只允许恢复 #17 原地址、TTL 600 和原备注。确认 #17 可用、权威和递归解析恢复、600 秒缓存窗口过去后，才允许按实际任务的精确 ID 清理候选。删除请求也先记日志，回执不明不再发；两次相隔至少 10 秒的明确不存在读回才算清理成功。若结果未明、记录漂移或 #17 未恢复，保留候选，不覆盖、不删除、不交回写权。
