# 代理退款与下级用户处置

## 操作边界

订单管理的“退款并封禁”只登记已核实的退款处置，不调用支付渠道退款，也不自动扣减充值余额。支付平台退款与余额结算仍须管理员单独核对。本次没有改动网关、节点程序或自动续费策略。

当订单用户有代理资料或直属代理用户时，必须先预览影响范围，再选择处理方式、填写原因并勾选确认。旧客户端直接提交代理退款会被拒绝，不会静默保留或冻结下级。

| 处理方式 | 原代理 | 直属下级 |
| --- | --- | --- |
| 保留 | 封禁、停用代理资格、清除登录会话 | 保留订阅、会话与代理归属；原代理渠道购买、续费可能受限 |
| 平台接管 | 同上 | 移除原代理归属，保留套餐、到期时间、流量和现有封禁 |
| 转移其他代理 | 同上 | 接收代理须启用、未封禁且未超用户上限；保留订阅与现有封禁 |
| 冻结 | 同上 | 封禁、清除会话，同步撤销节点资格；套餐数据保留，需人工恢复 |

仅处理 `v2_agent_user` 中的直属用户，不递归处理下级代理的用户，也不处理普通邀请码邀请关系。多级关系须另行核查。

转移仅改变用户归属；只有用户邀请人恰为原代理时才同步改变邀请人。不会转移原代理或下级余额、历史订单和佣金账本，不追溯重算其他订单。

## 安全与审计

- 确认令牌绑定订单、原代理及直属用户归属/套餐/封禁状态；预览后发生这些变化必须重新确认。普通流量计数不会导致频繁失效。
- 原代理、订单、归属与用户在事务内加锁。禁止转移给原代理、原代理的下级、未启用/封禁代理或循环关系账号；异常管理员/员工归属不能冻结或转移。
- 下级处理、原代理停用、会话清除、节点状态同步、订单标记与佣金撤回处于同一事务；失败回滚。实时节点通知沿用提交后发送机制。
- 同一订单重复提交返回已有结果，不再撤回佣金，也不影响后来新增的用户。
- 原有封禁原因不被关联冻结覆盖。停用/封禁代理不能重新开通代理或通过旧资料继续管理、创建用户。
- `v2_order.agent_refund_disposition` 保存方式、人数、接管方、原因、管理员及时间；订单详情展示记录。

## 上线要求

1. 先备份并部署后端，执行新增迁移 `2026_10_11_100000_add_agent_refund_disposition_to_orders.php`，再更新管理端。管理端遇到缺失预览接口时停止操作，不降级为旧流程。
2. 未在这里修改任何线上用户、发起退款或运行线上迁移。已有退款记录不会被自动补处理，应人工核对。
3. 本地 SQLite 回滚/重试测试不是 MySQL 真并发或实际支付退款验收。上线前在隔离环境复核退款与创建用户、转移、佣金结算并发，以及实际节点接收撤销通知。

本功能不改变正常代理用户购买时的数据路径，不增加节点轮询或驻留缓存。
