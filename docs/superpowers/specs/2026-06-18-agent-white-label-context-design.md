# Agent White-Label Context Design

## Goal

代理需要拥有自己的站点品牌和业务隔离能力。用户即使访问主域名，只要已经属于某个代理，也必须继续使用该代理的网站名称、公告、工单、套餐价格、支付方式和余额限制。

## Current State

- 代理域名已经通过 `v2_agent_domain` 按 `Host` 识别。
- 代理套餐售价、代理支付方式、代理订单上下文和余额 hold 已经存在。
- 用户端公开配置仍主要来自全局 `/guest/comm/config`，站点名、Logo、落地页主题没有代理覆盖层。
- 代理创建或绑定的下级用户已经有业务归属，但这个归属还没有统一沉淀成前后端都能使用的“代理上下文”。

## Scope

一期目标只做稳定的白标和业务隔离，不开放高风险自定义。

包含：

- 代理网站设置：网站名、Logo URL、落地页主题、主色调、客服信息、公告。
- 代理上下文解析：域名、登录用户归属、注册或邀请归属。
- 公开配置覆盖：代理域名或代理用户访问时，覆盖站点名、Logo、主题、客服和公告。
- 公告隔离：主站公告与代理公告区分展示。
- 工单隔离：代理用户工单归属代理；代理只能看自己的下级工单，管理员看全部。
- 订单隔离：代理用户访问主域名购买，也使用代理售价、代理支付和代理余额检查。

暂不包含：

- 自定义 HTML、JS、CSS。
- 自定义订阅协议或节点规则。
- 自定义邮件发件人。
- 代理完全隐藏平台身份。
- 代理自定义知识库全文内容。

## Context Resolution

后端新增统一的 `AgentContextResolver`，所有代理相关业务只读取它的结果。

解析优先级：

1. 当前请求 `Host` 命中有效代理域名。
2. 已登录用户属于某个代理下级。
3. 注册、邀请或代理落地页保存的代理归属 token。
4. 无代理上下文，使用主站默认配置。

如果域名识别和登录用户归属冲突，已登录用户归属优先用于订单、工单和公告；域名只作为展示来源，避免用户在别人代理域名下绕开原代理关系。

## Data Model

新增 `v2_agent_site_setting`：

- `id`
- `agent_user_id`
- `agent_domain_id` nullable
- `site_name`
- `logo_url`
- `landing_theme`
- `accent_color`
- `support_name`
- `support_url`
- `announcement`
- `seo_title`
- `seo_description`
- `enabled`
- `created_at`
- `updated_at`

规则：

- `agent_domain_id = null` 表示代理默认配置。
- 有域名配置时优先域名配置；没有则回退代理默认配置；再没有回退主站。
- URL 只允许 `http` 和 `https`。
- 颜色只允许 hex。
- 文本字段限制长度，不允许 HTML。

## Public Config

`/guest/comm/config` 增加代理覆盖逻辑：

- 保留原有全局字段。
- 当请求能解析出代理上下文时，返回覆盖后的 `app_name`、`logo`、`landing_theme`、`theme_config`、客服信息和公告。
- 增加 `agent_context` 摘要，前端可判断当前是否处于代理站点。

前端仍优先读取已有配置字段，减少页面改动。

## Announcements

公告分两类：

- 主站公告：默认给所有用户看。
- 代理公告：只给代理域名访问者或代理下级用户看。

展示规则：

- 未登录且访问代理域名：显示代理公告。
- 已登录代理下级用户：显示代理公告，即使访问主域名。
- 普通用户：显示主站公告。

## Tickets

工单新增代理归属过滤：

- 代理下级用户提交工单时写入 `agent_user_id`。
- 代理后台只能查看、回复自己下级用户的工单。
- 管理员后台保持查看全部，并显示代理来源。
- 用户端不暴露“代理归属”字段，只展示正常工单体验。

## Orders And Payments

所有下单前后都使用统一代理上下文：

- 下单前确认代理售价。
- 下单前检查代理余额是否足够。
- 支付方式优先使用代理启用的支付方式。
- 支付回调成功前再次检查代理余额。
- 余额不足时订单不能开通，并给用户明确提示。

## User Interface

`keli-user` 代理中心新增“网站设置”页签：

- 域名选择。
- 网站名称。
- Logo URL。
- 落地页主题。
- 主色调。
- 客服名称与客服链接。
- 站点公告。
- 保存按钮。
- 右侧/下方展示轻量预览。

`keli-admin` 增加管理员可见项：

- 代理网站设置是否允许开启。
- 管理员查看代理站点配置。
- 管理员禁用某个代理的白标配置。
- 工单、订单、支付流水列表显示代理来源。

## Error Handling

- 代理设置无效时不影响主站，自动回退主站配置。
- Logo 或客服链接格式错误时拒绝保存。
- 代理域名未验证时，不允许绑定域名级白标，只能保存代理默认配置。
- 代理余额不足时，下单和回调都返回明确错误。

## Testing

后端：

- Host 命中代理域名时返回代理上下文。
- 已登录代理下级用户访问主域名时仍返回代理上下文。
- 域名与用户归属冲突时订单按用户归属处理。
- `/guest/comm/config` 能正确覆盖站点名、Logo 和主题。
- 代理公告、工单、订单只命中对应代理。
- 余额不足时下单失败，回调也不会开通。

前端：

- 代理网站设置表单校验。
- 站点配置覆盖后，登录、注册、落地页和仪表盘显示代理品牌。
- 代理中心网站设置保存后能刷新预览。

## Rollout

1. 先上数据表和 resolver，不改变现有行为。
2. 接入 `/guest/comm/config` 代理覆盖。
3. 接入订单、公告、工单的代理上下文。
4. 接入用户端“网站设置”。
5. 接入管理端审计和开关。
