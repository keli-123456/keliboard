最多三个阶段：健康源分支的源基线、候选切换前、切换后真实解析路径；每阶段每传输三个不同的 32 字节帧，不能丢失、重复、多出或重放。测量最多 24 秒、挑战 45 秒、候选证明 120 秒。测试转发进程非 root、单核 CPU 25%、内存 448 MiB、swap 0、任务 96；合成账号配额 1 MiB、应用载荷每方向最多 64 KiB，不改正式账本。

## 清理、诊断和停止

成功、失败、停止或到期均停止新派发：**先恢复故障并保全证据，清源/候选和 DNS，控制机最后删除**。

1. 通用 CLI、字段级、DNS 和替换首错仅保存白名单字段、布尔判定及安全类别，不导出原始消息/日志/响应正文、IP 值、私密路径、签名或凭据。`replacement-first-error.json` 必须独立本地读回；CLI 丢回包时从控制机清理导出恢复同一首错，后续错误不能覆盖它。缺少应有证据不能判通过，但不得因此无限保留计费资源或重跑阶段。
2. 清理分类为 `not_dispatched`、`dispatched`、`needs_review`。只有事务内完整步骤史、原生身份绑定、终态、无派发/云身份/bootstrap 活动的证明，加上完整无冲突云库存，才能省略未创建候选的云资源核对。缺 ID 不够；已派发、丢回执、矛盾证明或不完整库存保留原意图核对和归属保护。
3. 即使候选确未派发，其任务仍在审计和私密清理/撤销清单内。停止测试服务和客户端，逐项核对合成账号、安装令牌、profile 撤销，以及临时 SSH/TLS、客户端、云/DNS 凭据副本、隔离 MySQL/Redis 和本轮自有卷清除；**控制机销毁不代替这些回执**。
4. 仅删除本轮原始意图/直接回执及当前账号、真实 ID、创建时刻、标签、归属一致的新资源。DNS 同时核对精确 ID 与完整名称清单；未激活部分创建的空备注仅按原始回执和完整元组规则处理，已激活记录必须完整匹配标记。禁止按前缀广删、按 IP 猜测或将 SSH 不通当已删除。
