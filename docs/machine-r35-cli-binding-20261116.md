# R35 isolated CLI authority and transport binding

## Scope

Local implementation and simulations only. No execution grant has been issued.
No production SSH/database, cloud API, DNS operation, deployment, cloud creation,
GitHub action, R34 execution or previous-round rerun occurred. Persistent automatic
switches, production queues/Horizon, default node version and tanzhen are unchanged.
This does not renew an earlier live approval. The existing frozen R35 archive and
its Linux evidence are historical inputs, not evidence for these new files.

## Bound Path

`MemberRound -> MemberControllerPort -> BoundControllerTransport -> fixed SSH
CLI -> MemberRoundBridge -> MemberRetryDriver -> native application services`.

- SSH remains key-only, BatchMode, IdentitiesOnly, StrictHostKeyChecking and
  UpdateHostKeys=no. The only RPC command is the fixed PHP entry. No RPC accepts
  shell commands, provider payloads, caller-selected task IDs or health verdicts.
- Schema 2 binds the run, grant ID, raw grant SHA-256, frozen bundle SHA-256,
  request ID, sequence, role and operation in both directions. Local key and
  known-hosts hashes and the control IPv4 are pinned, not discovered or relaxed.
- The controller pins its Linux machine-id hash, runtime/application file hashes,
  source identities, selected account/revision, native plan, service snapshot and
  exact A/B record-set scope. The grant is a separate root-owned private file,
  never shipped in an unarmed package or generated by this adapter.
- The fixed entry checks the isolated application directory and loopback-only
  MySQL/Redis configuration before application providers boot. URL/cluster/read-
  write overrides, cached configuration and unexpected cache connections are
  rejected. Its journal is private, locked and written before mutation dispatch.
- The ordinary application execution gate is unchanged and denies execution.
  Only the fixed isolated CLI uses a typed, process-local capability. The allowed
  policy/machine lists are scoped to A. Rotation, background runner and persistent
  settings stay closed. Configuration, execution gate and bus dispatcher are
  restored in `finally`, including exceptions.
- Native fallback jobs use Laravel's NullQueue inside that CLI scope only.
  Native service methods still execute synchronously. No queue or Horizon
  configuration is edited and no deferred job retains the temporary capability.

## State And Cleanup

- The two source tasks must already be prepared and identity-pinned. Registration
  uses three distinct real report observations; it grants identity, not health or
  forwarding. Repeated reports do not replace fresh observations.
- Only A runs. Native labels/ownership markers, capacity, concurrency, failure
  threshold, two absence reads, cooldown and two-candidate ceiling are retained.
  B's task/identity/DNS facts are compared around each step without recursively
  re-entering the driver's execution guard.
- RPC and host journals persist mutation intent first. Missing replies or process
  crashes do not authorize another step with a fresh request ID. Recovery stops
  further work and reads original native task/attempt identities.
- A stop marker is irreversible. Expiry stops new work at the cleanup reserve;
  scoped status, stop, inspection and final deletion remain available afterward.
  Final deletion requires stop, exact original task IDs and ownership checks.
- Host cleanup retains the existing ordering: restore faults; clean task roles;
  clean pinned DNS/private files and export evidence; delete the controller last.
  Explicit absence needs two reads at least ten seconds apart. Unknown identity
  or unresolved create outcome is held for reconciliation, not called absent.
- `resources_cleaned` and `acceptance_passed` remain separate. HY2 is not inferred
  and does not become a gate for this V2 main-flow simulation.

  Windows environment before opening an application or network connection.
