## 隔离资源方案

首轮原方案仍拟采用 Linode。DigitalOcean / Vultr 的原生创建、回连和验收适配器现已在本地接通模拟流程，但不代表真实环境验收通过。两家的服务商专用模板白名单默认仍为空，`localChecks()` 会阻断未经审定的模板；所有真实执行开关保持关闭。

```text
独立测试面板
  独立 MySQL/Redis 服务、队列、守护和应用密钥
  独立 HTTPS 回调入口
       |
       | 后续另行授权的一次性创建意图
       v
1 台全新非业务候选机
  cloud-init 安装 kelinode-rs
  本次任务独有的安装 ID、发行物和 SHA256
  专用逻辑机器、专用节点组和临时测试身份
       ^
       | UDP 24443 内的真实 TCP / UDP 转发
独立受控验收客户端位置
  HTTPS 验收 worker、固定回显目标、有限期 profile
```

“单台”只指候选云机，不代表验收端也运行在候选机内。验收客户端应位于候选机之外，可以使用另行授权的既有非业务环境，不要求现在增购机器。完整的旧机替换测试会同时涉及旧源机和新候选机，属于另一阶段；本轮不验证真实 DNS 切换。

控制面板和验收 worker 拟放在另一台专用非业务宿主上，各自使用独立服务和资源边界；宿主地址仍待确认，不默认占用正式面板或 tanzhen 所在机器。下列名称和限额均是草案，尚未创建或配置：

- 环境命名空间拟为 `keli-acceptance-<run-id>`；数据库、Redis 实例、队列、Horizon 主进程、目录和服务名均归属于该次环境。只有 Redis 前缀不同不算完成隔离，容器不使用业务网络或挂载正式数据卷。
- 使用全新应用密钥、测试管理员、专用逻辑机器、节点组、策略、安装 ID 和有限期测试身份。只导入必要的版本化结构与合成资料，不复制正式 `.env`、数据、账号、订阅或云任务，不恢复正式数据库备份。
- 控制进程、验收 worker 和回显服务分别限定账户与进程组。worker 按现有样例采用非 root、`CPUQuota=25%`、`MemoryMax=384M`、`TasksMax=64`、`GOMAXPROCS=1`；这些是受控验收限额，不作为吞吐性能结论。
- 节点入口只放行验收端精确来源 IP，回显仅回环可见；候选机的转发路径必须只允许 `127.0.0.2:24444`。管理回调、下载和 ICMP 探测应与测试转发权限分别核验，不得因为需要管理联网而放开测试身份访问任意目标或云元数据。
- 以上网络边界须在获准搭建时验证，尤其是回环目标许可与默认私网拦截的兼容。不能通过关闭全部私网防护来让回显通过；无法实现精确限制时阻断验收，不将本方案视作已有运行时保障。
- 首轮分组只拟选一个独立 Linode 测试账号，固定同一创建意图、发行物与来源身份，不启用账号自动轮换。停止、超时、失败均不重发付费创建，不删除或关闭云机，资源保留及后续处置单独记账并申请授权。
- 客户端 profile 每次有效期不超过 1 小时，不能自动续期；结束须核对客户端进程与私密文件、服务端身份、证书/profile 和回显服务的撤销清理。云机仍保留必须明确记录，不能将测试组件清理完成写成删机或费用结清。

当前向导要求本次独立创建任务的来源记录。已有普通机器、旧安装 ID、历史回执、同名版本或旧云资源不能充当新建成功证明。新方案不导入 tanzhen 脚本，`source_ref` 保持空。

| R09 | 入口与证书方案 | 核对 origin、verifier 地址、TLS 信任、目标/端口白名单和回调方向；不得跳过证书校验或允许任意 URL | 端口和节点 TLS 方案已拟定；入口、占用、网络边界和连通性尚未实测 |
| R10 | IPv4 证据口径 | 读取隔离配置和既有样本：任一已配置目标可达为绿；全失败须有同来源健康基线及连续完整失败样本；过期、未知或无来源归属不判红，IPv6 不作依据 | 规则已核对；目标、实时样本待提供 |
| R11 | worker 及临时身份 | 核对程序哈希、私有文件权限、非 root 运行、进程/内存边界、profile 的精确目标 IP 和有效期，以及身份撤销方案 | 设计和样例已存在，实际宿主与边界待验收 |
| R12 | 回执和成本结案 | 明确只保留任务标识、阶段、聚合计数、回执摘要及清理状态；云资源保留、删除申请及费用核对各有责任人 | 待确定责任人与处置意向 |

“只读”不包含保存策略、刷新云清单、运行凭证健康检查、采集费用基线、生成任务或执行验收。这些动作可能写缓存、审计或任务记录；本轮均不调用。只读清单不得直接调用 `queue`、`enroll`、`verify`、取消任务、迁移、安装、重启或任何 DNS 写入。

## 未来真实验收的独立准入

以下步骤只作为后续方案，不在本轮执行。

1. 补齐参数表中仍待确认的项目和配套资料，完成隔离边界复核。资料齐备只表示可以申请开测，不表示向导的 `creation_allowed` 应变为真。
2. 单独授权独立测试环境的搭建、只读服务商核验和有限期临时身份。只读 Token 或分组名称不能代替创建权限，生产账号的权限不因此扩大。
3. 单独授权最多一台候选机的一次性手动创建。只在隔离测试实例内批准指定机器和策略的白名单及所需单台创建/验收门槛；不修改正式配置，不开放全局自动创建、自动轮换、DNS 切换或原生自动故障转移硬闸。当前没有浏览器或环境变量开关可绕过这些限制。
4. 创建前重新取得有效预检；其回执有效期为 120 秒，并绑定管理员、策略修订、发行物和目录/凭证上下文。只沿原请求 ID 跟进，超时或结果未知只核对原意图，不自动换账号或再发创建请求。
5. 核对新安装 ID、创建标记、云资源身份、公开 IPv4、派发后的 Agent/节点上报、进程会话、二进制摘要和配置投影，再执行受控公网转发验收。安装脚本最长 600 秒，创建任务期限当前默认 1200 秒；超时不等于资源不存在。
6. 结束时先核对临时客户端、socket 和私密文件清除，再由身份所有者撤销服务端临时身份和 profile。单独记录云机及预算仍然保留的状态；任何删除、关机、预算释放或扩大测试范围都需另行授权。

独立单台验收服务与自动故障转移原生执行桥是不同入口；临时授权隔离单台测试不等于开启全局自动化。当前本地所有执行门槛保持原样，没有为这份准备方案做任何放行。

## 未来通过条件与限制

- 候选机必须来自本次独立任务，安装 ID、发行物、节点及公开 IPv4 对应一致，且没有正式业务或 tanzhen 资源混入。
- 国内 IPv4 探测按项目口径记录，不能把 ICMP 结果当成全部协议的公网转发证明；后者单独测试。
- worker 仅允许本策略、本候选公开 IPv4 和约定节点/端口；profile 有效期须在核验时至少剩余 30 秒且不超过 1 小时，续期须显式授权。
- 每个节点 TCP 和 UDP 都必须收到原始 3 个不同的 32 字节回显帧，无缺失、无重复且摘要一致；TLS 身份、签名、单次 challenge 和回执时效均通过，临时客户端清理完成。
- 这 96 字节是每传输的合成应用负载，不是完整网络计费字节，也不是吞吐峰值或 P99 指标。单台 HY2 就绪通过，不代表其他协议、多地区、自动换机或 DNS 切换已验收。
- 错误密码、错误 TLS 身份、服务端身份撤销和重放等负例，须在另行批准的公网测试用例中单独记录；不能把已有回环测试结果填作公网通过。
- worker 不会创建或撤销服务端账号；`cleanup_complete` 不能替代临时身份撤销证明。任务默认 `delete_strategy=keep`，取消、超时或客户端清理完成都不代表云资源已经删除或费用已经结清。

- 当前原生 owned-DNS 替换仅支持 Cloudflare A 记录。Aliyun 仍可用于普通实例解析绑定，但不能用于本次原生替换；应在建机前阻断，不得为了继续测试而跳过归属校验。DNS 凭证固定，不随云凭证自动轮换。
- 后续获准搭建隔离库时，须先检查 `2026_11_09_140000_add_machine_dns_readback_state.php` 的四个读回状态字段。缺少迁移时保持 DNS 不可执行；已使用的读回证据不允许通过降级迁移删除。本轮没有执行正式或隔离库迁移，仅测试用内存数据库应用了该结构。
- DNS 验收应分别记录：单次写入意图、精确归属、服务商读回次数及下次核对时间、转发证据时效、外部解析及 TTL 传播。服务商读回最多 12 次，结果未知只核对原请求，不重复写入、不自动回滚，也不将服务商读回当成全球传播完成。
- 真实轮换验收须另行准备同组专用测试凭证和可验证的账号归属，并单独授权。仅测试确定拒绝后的安全选择、原请求未知时的禁止轮换、撤权和停止边界；不能以真实反复建机来制造配额/账单故障。Vultr 当前无法取得所需稳定独立账号身份时，应记录阻断，不能用邮箱、Token 名称或分组名称替代证据。
- 当前仍没有 API 凭证、已批准测试预算或可用隔离宿主。上述项目仅进入清单，未创建、部署、连正式库或操作 tanzhen，未打开任何真实执行开关。

## 服务成员记录集的模拟边界

新增的服务 DNS 记录集将“服务 / 域名”和“成员 / 地址族 / 线路”分开建模，支持在本地模拟 Cloudflare、阿里云多线路及 A/AAAA。它不迁移既有业务解析、单 A 归属记录或 tanzhen 记录。带记录集的服务不能进入旧单记录原生桥或旧单记录预演，须使用记录集专项模拟。

新增迁移仅在内存 SQLite 测试库运行。记录集草稿与模拟审计需保留，降级不能丢掉归属槽位或让父服务先被删除。保存草稿会推进服务修订；真实创建、自动轮换、原生调度和 DNS 切换开关均未改变。

后续真实验收须另行确认以下项目，本轮均未执行：

- 独立域名与精确记录集归属；每条成员、线路和 A/AAAA 的记录 ID、标记及完整分页视图。不能将现有非托管记录按相同 IP 自动认领。
- 阿里云账号的实际解析线路权限、付费版本、最小 TTL 和额度。模拟中的六个线路标识及 TTL 范围只验证输入和请求结构，不代表账号已获这些能力。
- 阿里云创建记录与写归属备注之间的中断点：必须有原创建请求明确返回的 ID，且恢复时重核身份。结果未知的未标记记录进入核查，不能凭地址匹配补写备注或重复建记录。
- 每个拟发布地址族的公开地址来源、新鲜节点身份和独立转发证据。只验证 IPv4 不能证明 IPv6 转发；国内 IPv4 探测规则仍保持不变。
- 部分线路/双栈成功、另一部分失败时的真实持久化、停止、对账和明确授权恢复。模拟“恢复旧地址”不授权线上自动回滚，也不替代服务商读回、外部解析及 TTL 传播检查。

记录集模拟不使用云/DNS HTTP 传输、正式数据库或原队列，不发送通知，不申请机器或凭证。当前只提供草稿、原请求模拟和查看结果，不提供真实记录集执行入口。

## 多记录执行内核的隔离验收边界

本轮将专项模拟接入共享的逐条执行内核，模拟 DNS 状态独立于任务日志保存。新增运行时表保存 120 秒工作租约、代次、下次核对时间和停止请求。新迁移仅用于内存 SQLite 测试；线上及独立 MySQL/Redis 均未执行。

- 每条操作先保存计划校验值、精确请求和派发边界。中断后只核对原操作；旧工作器不能回写过期回执或清除新工作器的租约。
- 停止请求不等待工作器锁，可阻止后续线路或地址族写入。已经在途的操作只能读回核对，不能假定没有发生；未知结果、创建后尚未写归属备注的记录保留待核查，不自动清理或回滚。
- 阿里云创建回执的记录 ID 和备注接口的请求回执分别处理。备注接口不返回新的记录 ID，必须以原创建 ID 和后续完整读回确认。结果未知的未标记创建不能凭 IP 认领。
- 读回最多 12 次，退避及预算持久化，进程重建不重置。模拟使用明确标识的虚拟等待；未到核对时间的内核步骤不会发起额外请求。
- 现有原生单 A 桥、真实创建、自动轮换和 DNS 硬门禁均未改变。新增 HTTP 适配器和底层多记录方法也先检查硬门禁，配置或请求参数不能启用。
- 后续真实验收仍需逐地址族的新鲜候选身份和独立转发证明、原生多记录准入绑定，以及隔离数据库上的多工作器崩溃/停止验证。模拟租约接续和 HTTP 假回执不是实际云机、服务商权限或 DNS 传播验收。

管理端可以查看“正在停止，等待已派发操作核对”和已核对条目数；旧版预演只读，不自动进入新执行器。本轮仅同步提交源码和本地管理端产物，未部署、未执行真实迁移，不操作现有 tanzhen；真实自动创建、自动轮换和 DNS 切换继续关闭。

## 原生准入与地址族回执绑定（本地）

本轮已在硬门禁之后接通原生记录集准入，不再让该类服务进入旧单 A 执行路径。新表保存每个尝试、地址族唯一的一次性回执及加密上下文，降级保留审计。模拟测试通过不能替代真实验收，也没有新增可开启真实执行的入口。

- 原实例和候选必须各自绑定任务、账号修订、云资源创建身份、安装 ID、版本校验值及机器权限。发布地址必须同时属于候选任务、资源、新鲜且同安装 ID 的 Agent 主动上报，以及服务商最新身份读回；不能拼接不同实例的 IPv4/IPv6，也不能仅凭请求来源 IP 认定。
- 每个拟发布地址族单独签发 schema 2 挑战，严格校验任务、尝试、原实例、目标 IP、进程会话、配置和拓扑摘要，以及所有节点的 TCP/UDP 精确回显和清理结果。旧 IPv4 回执不能替代 IPv6。国内连通性判定仍只探测 IPv4。
- DNS 子任务的原意图、记录集快照、不可变写入计划、初始库存、原实例及回执链接独立加封；只有完整原记录归属匹配才准备切换，不导入、不认领未托管记录。身份变化、过期、撤权、串单、模拟回执不能派发。
- 多成员 DNS 交接串行，只承认同一轮已经完成并加封的前一成员交接。中断继续原子任务；已派发但丢失回执只读回核对，不重发。父任务停止会撤销子任务代次，在途或部分写入进入待核查，不自动回滚。
- 所有记录集都必须在新鲜窗口内完成读回，才能事务性切换活跃实例并保留旧资源。原来的 120 秒验证时效不延长，慢请求或大规模交接超时进入核查，不自动续签验收。工作器数量、队列路由和限额均不改。

真实阶段仍待独立授权：隔离 MySQL/Redis 上的原生多工作器崩溃和停止验证、各地址族真实转发、服务商创建身份、账号实际解析线路和 TTL 权限，以及外部解析传播。本轮仅内存 SQLite 和假云平台、假 DNS、假签名回执；不接正式库、不部署、不建真实机器、不操作 tanzhen，真实自动创建、自动轮换和 DNS 切换继续关闭。
