节点连接问题自助排查

先确定失败发生在哪一步：订阅下载、配置导入、节点连接，还是应用上网。保留当前可用配置，每次只改变一个条件，避免一次重装、重置和换内核后无法定位原因。

第一步：检查账号和订阅更新结果

  1. 在用户中心确认套餐是否有效、流量是否用尽、账号是否存在限制。
  2. 确认复制的是订阅链接，而不是官网或导航页地址；订阅曾重置时，重新复制当前链接。
  3. 在客户端执行一次更新，记录成功、HTTP 错误、超时或格式错误。更新失败后列表可能仍显示旧缓存，不能把旧列表当成刚下发的配置。

按症状继续处理

订阅下载超时或 HTTP 错误

先做：核对站点公告、切换网络、重新复制订阅；不要立即重置。

仍失败时提供：发生时间、客户端版本、错误码；截图遮住链接。

unknown proxy type 或配置解析失败

先做：核对导入格式、内核及版本；参考“客户端与内核兼容说明”。

仍失败时提供：协议名称、内核版本和去除凭证后的错误原文。

更新成功但缺少部分节点

先做：检查套餐权限与客户端筛选；证书或 ECH 等待就绪的节点也可能暂不下发。

仍失败时提供：缺少的节点名称、两端客户端及内核版本。

TLS、证书或指纹错误

先做：校准设备时间，再从可信站点更新订阅；不要关闭验证。

仍失败时提供：错误类型、节点名称、首次发生时间。

节点超时或显示 -1 ms

先做：测试另一个节点、另一种网络，区分单节点故障与本地网络问题。

仍失败时提供：失败节点、可用对照节点、Wi-Fi 或移动网络及测试时间。

网页正常但游戏、语音或 UDP 应用失败

先做：确认应用被代理、客户端开启 UDP，比较其他网络；H3、HY2 等依赖 UDP 的连接可能受网络限制。

仍失败时提供：应用名称、协议、网络类型，以及 TCP 是否正常。

延迟测试成功但应用不能上网

先做：检查系统代理、规则命中与应用代理支持，暂停其他代理软件；TUN 仅在确有需要时配置。

仍失败时提供：受影响应用、规则模式、系统代理或 TUN 状态。

同一个节点换内核后才失败

固定其他条件，对照记录 Xray、sing-box 或 Mihomo 的版本与报错。可临时使用已经验证可用的配置，不要仅凭这个现象认定服务器必须降级。

提交工单前整理这些信息

  • 设备系统、客户端名称及应用版本、实际内核及版本。
  • 节点名称或协议、发生时间和时区、错误原文、一个可用的对照结果。
  • 截图遮住完整订阅、Token、UUID、密码及私人收款信息；日志只截取相关错误，不上传完整配置。

订阅可能泄露时才按安全流程重置。一般连接失败不需要反复重置、关闭证书校验或以管理员权限运行所有客户端。
