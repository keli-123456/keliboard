# 订阅风控 (Subscription Control)

## 当前处置契约

行为异常是排查线索，不是订阅泄露、账号恶意或节点被墙的证明。检测保持启用，但不再把旧配置中的动作名称统一升级为重置凭据。

| 场景 | 当前处理 | 凭据影响 |
| --- | --- | --- |
| 明确命中来源黑名单、UA 黑名单、仅拒绝 UA | 拒绝当前订阅请求，HTTP 403 | 不重置；原有明确黑名单的来源 IP 策略保留 |
| 旧客户端标识、未知客户端、多 UA、多地区、在线地址数超限 | 记录 observe 事件，正常继续生成订阅 | 不重置，不自动断开连接 |
| 同源批量拉取、组合泄露风险、订阅 IP 数/频率超限 | 当前请求 HTTP 429，附 Retry-After 和 no-store | 不重置，不影响其他账号的凭据 |
| 管理员确认泄露 | 使用现有手动重置入口，明确确认后执行 | 可能同时轮换 token 和 UUID，旧配置需重新导入 |
| 明确启用的阅后即焚 | 达到次数上限后的请求被拒绝，并轮换 token 和 UUID | 保留该功能的原有明确用途，不与行为可疑混同 |

客户端白名单中的浏览器、空 UA、脚本仍可仅拒绝本次请求。UA 可伪造，不能据此认定用户身份或攻击意图。

429 是对本次订阅请求的限制，不是对节点转发带宽限速。至少等待 60 秒后再试；如果仍超过所设检测窗口的额度，应继续等待窗口恢复。不会承诺 60 秒后必定放行，也不会自动扩大成全账号凭据重置。

只观察的事件不增加拦截计数、不发送用户处罚通知、不覆盖用户最近一次真实拦截记录。组合风险规则若同时命中，仍可以对该次请求返回 429。

泄露保护即使分数达到阈值，缺少至少两类行为佐证时仍只观察。同一 UA 派生的多个加分只算一类；低流量、缺少在线记录和云厂商标签不是额外的独立行为佐证。观察、限流以及历史行为重置事件不会被节点托管路由学习成封禁前缀。

## 节点事件与订阅生成证据

节点事件采集默认关闭，自动 AI 调查另需授权，不替代独立连通性验证，也不会处罚账号。

- 在线证据来自既有上报，不是逐连接日志；不会增加节点采集或上报频率。
- 内置 12 种订阅格式在实际加入输出节点后记录生成证据，兼容性筛除、空输出和失败响应不作为生成记录。同一节点配置的导航/状态别名去重，不额外增加记录。第三方导出器未接入时没有此类证据，不能据此认定没有生成。
- 生成记录含账号、归属站点、时间和配置指纹；节点地址、原始配置、密码、令牌和用户 IP 不进入新记录或任务队列。配置指纹只描述当时导出配置，不等于节点应用回执或历史修订编号。
- 新记录独立于 AI 自主观察开关，但受节点事件采集授权约束；不调用模型。响应路径只做有界内存处理、缓存额度检查和一次异步派发，不同步写 SQL、不重试、不改变订阅内容。缓存、队列或存储失败可以造成缺口。
- 每响应最多 64 个受管节点，每账号每分钟最多 2 条，全局每分钟最多 30 条；独立原始记录保留 24 小时。异常调查最多核对前 30 分钟的 1000 条记录、20 个账号、每账号 8 个节点配置指纹。截断与缺失均不能解释成完整覆盖。
- 回溯依据生成时的机器绑定，不把节点当前绑定当作历史事实；归属站点或凭据已变化的记录不再归入当前身份。没有在线样本的账号也可能有生成记录，两者分开展示。
- 服务端生成不证明客户端收到、连接、使用、分享或导致封锁；AI 只获得化名和有界摘要，不获得真实账号 ID。事件冻结证据仍随事件保留 7 天，不冒充全量审计或真实用户设备验收。

## 配置兼容与升级

- 原有检测开关、名单、计数窗口保留，不自动回写生产配置。
- 历史动作值仍可存储，但实际行为受上面的服务端分级契约约束，不能靠旧的 reset_token_uuid 值将弱信号升级为重置。
- 管理页场景摘要显示实际处置，而不是照抄历史动作字符串。历史事件仍保留当时实际执行的动作。
- 管理页的“应用默认策略”只有管理员明确应用才写入；该预设关闭阅后即焚。升级本身不会关闭已启用的阅后即焚。
- 本次规则行为和可信来源逻辑变化会使旧的 AI 执行评测上下文失效，应重新评测，不沿用旧的执行准入。
- 本次实现不需要升级 kelinode-rs，也不提高探测或用户上报频率。

## 可信出口与可信代理

这两项不是同一种权限：

- trusted_egress_ips：管理员确认的自有出口 IP/CIDR，用于降低同源共享和 IP/地区变化造成的误报；不会因此信任转发头。
- trusted_proxy_cidrs：允许解析真实客户端转发头的明确代理链路，应只配置受控反代及实际使用的 CDN 地址段。
- 自有网站/订阅反代：仅对管理端已启用、具有新鲜机器状态的受管反代，单独赋予转发头身份。上报过期、时间异常或非公网地址不得获得该身份；关闭反代后的身份缓存最多保留 30 秒。

自动出口识别仍可参考管理端配置的节点 host/ips 及新鲜机器报告。DNS 仅解析节点 host，跳过 Cloudflare 边缘地址；TLS SNI、Reality 伪装域名、WS Host 不再作为可信出口来源。入站域名不必然等于出站出口，无法确认归属时应关闭自动 DNS 识别并维护手工出口清单。

手工或第三方反代不能只填入“可信出口”来获得转发头权限，必须单独核对可信代理配置。旧的自动信任缓存使用新命名空间，不沿用 SNI/Host 推导出的旧结果。

受控反代必须覆盖或追加实际连接来源到 X-Forwarded-For。解析从右向左跳过已知代理，忽略客户端伪造的左侧前缀。非直接 Cloudflare 链路不再使用 CF-Connecting-IP、True-Client-IP 或 X-Real-IP 回退；缺少有效代理链时只保留连接对端，不猜测用户来源。

## 凭据与日志

- 凭据重置日志仅保留账号标识和结果，不记录旧 token、新 token、UUID 或完整订阅链接。
- 写入失败仅记录固定错误类型，不把可能携带 SQL 绑定值的异常正文写入日志。
- 阅后即焚的凭据写入未确认成功时返回 503，不显示“已重置”，也不继续暴露订阅。
- 缓存清理或成功日志失败不能把已经持久化的凭据变更错误报告为未写入。
- 修改代码不会清除历史日志。上线前应授权核查历史日志、日志备份和访问权限，再决定脱敏或凭据轮换范围；不得盲目删除业务日志或批量重置用户。

## 数据、证据与性能边界

- 计数窗口和自动出口结果使用有上限的缓存；来源归属与 ASN 查询保留原有缓存。
- 风控事件可以写入现有事件表；并非所有数据都只在缓存中。保留期限由事件配置控制。
- 在线地址数不等于设备数，多地区、共享出口、旅行和网络切换均可能是正常使用。
- 订阅生成记录不证明客户端实际收到、使用或泄露了节点信息。
- 国内出站探测只是连通性线索，不单独证明入站业务端口可用或节点被墙。
- AI 调查、旧规则、明确黑名单和管理员手动操作各自保留授权边界，不互相扩大权限。

## 上线核对

1. 在本地测试观察请求仍返回正常订阅，限流请求返回 429 且不轮换凭据。
2. 核对实际反代链路；对手工反代只配置确实受控的代理地址，避免过宽网段。
3. 核对阅后即焚是否为当前站点明确需要的功能。
4. 检查历史日志的凭据暴露范围，必要时制定有通知和恢复路径的轮换方案。
5. 规则变更后重新运行 AI 对照评测；不要因一次节点异常自动处罚相关在线账号。
