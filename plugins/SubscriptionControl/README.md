# 订阅风控插件 (Subscription Control)

## 功能介绍

订阅风控插件为 XBoard 提供了强大的订阅链接访问控制功能，帮助防止节点被恶意扫描和滥用。插件运行状态完全基于缓存保存，无需额外创建数据库表，轻量高效。

### 主要功能

1. **UA黑名单** - 拦截特定User-Agent的访问请求
2. **同源批量订阅检测** - 同一 IP/UA 短时间拉取多个用户订阅时重置订阅 token 和节点 uuid
3. **订阅泄露保护** - 高风险订阅拉取直接重置凭据，避免旧订阅继续暴露真实节点
4. **在线唯一IP阈值** - 当前在线唯一IP数超过阈值时自动重置订阅凭证
5. **邮件 / TG 通知** - 命中风控后通过邮件、Telegram（已绑定时）发送提醒
6. **客户端UA白名单** - 只允许指定客户端类别拉取订阅，未知客户端可观察或重置凭据
7. **多UA拉取检测** - 同一个订阅 token 在短时间内被多个客户端类别拉取时触发风控
8. **多地区拉取/在线检测** - 同一个订阅或同一个用户短时间内出现多个地区时触发风控
9. **IP限制** - 限制时间窗口内不同IP的访问数量
10. **访问频率限制** - 限制用户的订阅拉取频率
11. **自动可信节点出口识别** - 自动读取节点地址和机器上报 IP，排除用户开着自有节点更新订阅造成的误判
12. **阅后即焚** - 限制订阅链接在指定时间内的使用次数

### 默认防护基线

面向 GFW 探测和订阅泄露场景，插件新安装后默认开启：

- UA 黑名单：社交平台预取、恶意扫描和明确脚本 UA 直接拒绝，并永久封禁真实来源 IP。
- 客户端 UA 白名单：只允许现代代理客户端拉取订阅；旧 Clash/未知客户端触发 token + uuid 重置。
- 订阅来源 IP 黑名单：国内常见云厂商来源默认 `block`，不重置用户凭证；自动拉黑的单 IP 只在订阅侧生效。
- 节点来源 IP 托管路由：自动生成云厂商 CIDR 的节点侧 source_ip 拦截规则并绑定到节点。
- 同源批量、订阅泄露、多 UA、多地区拉取、在线多地区检测：默认开启，命中后重置 token + uuid。

## 安装方法

1. 将插件文件夹 `SubscriptionControl` 复制到 `plugins/` 目录
2. 在管理面板的插件管理页面启用此插件
3. 根据需求配置插件参数

## 配置说明

### UA黑名单设置
- **启用UA黑名单**: 开启/关闭UA检测功能
- **UA黑名单列表**: 每行输入一个关键词，支持模糊匹配
  ```
  BadBot
  crawler
  spider
  python
  wget
  curl
  ```

### 在线唯一IP阈值
- **启用在线唯一IP数阈值**: 开启/关闭此功能
- **在线唯一IP数阈值**: 例如设置为10，表示当用户当前在线唯一IP数大于10时触发
- **启用邮件通知**: 命中风控后给用户邮箱发送提醒
- **启用 TG 通知**: 命中风控后，如用户已绑定 Telegram，则发送提醒
- **通知冷却时间**: 同一用户同一风控类型在冷却期内只发送一次通知，避免刷屏

**触发效果**：
- ❌ 当前订阅请求会被拦截（403）
- 🔄 自动重置用户 `token + uuid`
- 📝 旧订阅链接和旧节点凭据一起失效
- 📧 可选发送提醒邮件
- 📱 可选发送 Telegram 提醒（用户已绑定 TG 时）
- 🖥️ 用户端订阅中心会显示最近一次风控事件
- ✅ 用户需要重新登录网站获取新的订阅链接

### 客户端UA白名单
- **启用客户端UA白名单**: 默认开启，用于阻止浏览器、社交平台预取和非客户端脚本直接读取订阅
- **客户端UA白名单**: 每行一个客户端关键词或内置分类
- **非白名单客户端处理策略**:
  - 社交平台预取 UA（Telegram、WeChat、QQ、Weibo 等）：放入 UA 黑名单，直接拒绝并永久封禁真实来源 IP
  - 普通浏览器、空 UA、通用脚本 UA：只拒绝本次订阅请求，不重置订阅 token 和节点 uuid
  - 旧 Clash、未知客户端：重置订阅 token 和节点 uuid
  - 明确恶意 UA：请放入 UA 黑名单，命中后永久封禁真实来源 IP，不重置用户凭证

旧配置中的 `observe`、`throttle`、`empty`、`block`、`reset_token` 会按上述分层策略归一化。订阅链接和节点 UUID 是同一个泄露面，凡是进入“重置”动作都会同时重置 token 和 uuid。

内置客户端分类会归一化版本号差异，例如 `mihomo/1.19`、`Clash.Meta/1.18`、`ClashX.Meta/1.118` 都归为 `mihomo`，避免正常客户端升级造成误伤。`Throne` 作为独立正常客户端分类处理。

### 同源批量订阅检测
- **启用同源批量订阅检测**: 默认开启。同一真实客户端 IP 和同一 UA 类别在短时间内访问多个用户订阅会触发风控
- **同源批量用户阈值**: 默认 3 个用户
- **同源批量检测窗口**: 默认 600 秒
- **同源批量命中策略**: 建议使用 `reset_token_uuid`，让批量探测来源触发订阅链接和节点凭据重置；历史的 `empty/block/throttle` 会自动归一为重置凭证
- **自有节点/可信出口 IP 列表**: 填写自己的节点出口、订阅反代出口或可信出口 IP/CIDR，命中后跳过该检测
- **自动识别自有节点出口 IP**: 默认开启，会自动合并手动列表、节点 IP、机器最近上报 IP

这个维度主要防“一个来源拿到多条订阅后批量验活节点”。插件只记录用户 ID 计数，不记录 token 明文。

### 自动可信节点出口
- **自动识别自有节点出口 IP**: 默认开启，自动补充可信出口，不需要把经常变化的服务器 IP 写死
- **信任节点机器上报 IP**: 默认开启，读取 `v2_server_machine.load_status.ip.public_ipv4/public_ipv6/panel_seen`
- **解析节点域名作为可信出口**: 默认开启。会解析节点 `host`、TLS SNI、WS Host 等域名；如果解析结果命中 Cloudflare CIDR，会判定为小云朵域名并跳过 CF 边缘 IP
- **自动可信出口缓存时间**: 默认 300 秒，动态 IP 场景建议保持 300 秒
- **机器上报 IP 有效时间**: 默认 900 秒，超过该时间未上报的机器 IP 不再自动信任

自动来源包括：
- 节点 `host` 中直接填写的 IPv4/IPv6
- 节点 `ips` 字段中填写的 IPv4/IPv6/CIDR
- 绑定机器最近上报的 `public_ipv4`、`public_ipv6`、`panel_seen`
- 节点 `host`、TLS SNI、WS Host 等域名的 DNS A/AAAA 解析结果（Cloudflare 小云朵域名会自动跳过）

如果用户开着你的节点访问订阅，来源 IP 会命中可信出口，插件不会把它当作“同源批量拉取”或“多地区泄露信号”。但 UA 白名单、脚本 UA 等非 IP 风险仍然有效。

### 订阅来源 IP 黑名单
- **启用订阅来源 IP 黑名单**: 默认开启，真实客户端来源 IP 命中黑名单时按策略处理
- **订阅来源 IP/CIDR 黑名单**: 每行一个 IP 或 CIDR，适合明确知道的网段，例如 `107.150.104.0/21`。该列表只用于订阅侧拦截，不会同步到节点 source_ip 托管路由
- **订阅来源 ASN 黑名单**: 每行一个 ASN，支持 `AS135377` 或 `135377`
- **订阅来源组织关键词黑名单**: 每行一个组织名关键词，基于 Team Cymru ASN 组织名匹配，例如 `ucloud`
- **订阅来源黑名单命中策略**: 固定使用 `block`，命中 IDC/云厂商来源时直接拒绝订阅请求，不重置订阅 token 和节点 uuid

默认预置 UCloud、阿里云、腾讯云、华为云等国内常见云厂商 ASN/关键词，例如 `AS135377`、`AS45102`、`AS45090`、`AS136907`、`ucloud`、`aliyun`、`alibaba`、`tencent`、`huawei cloud`。该功能默认开启。命中自有节点/可信出口 IP 时会跳过黑名单，避免用户开着你的节点更新订阅被误拦。

节点侧托管路由只同步云厂商 CIDR、BGP 前缀、内置高置信前缀和近期事件学习出的云厂商前缀。恶意 UA 自动写入的单 IP 黑名单不会下发到节点，避免长期累积后增加节点连接判断成本。

### 订阅泄露保护
- **启用订阅泄露保护模式**: 默认开启，对每次订阅拉取进行风险打分
- **命中策略**: 建议使用 `reset_token_uuid`，让疑似泄露订阅立即失效并要求用户重新获取；历史的 `empty/block/throttle` 会自动归一为重置凭证
- **严格模式**: 节点正在被针对性封禁时可开启，同一订阅换新拉取 IP/UA/地区、缺少在线地区证据都会加分
- **重复命中升级**: 默认开启，同一订阅反复命中后会升级到 `reset_token_uuid`
- **触发分数**: 默认 80 分
- **检测窗口**: 默认 600 秒

风险分主要来自：
- 脚本、浏览器、空 UA 等非真实客户端拉取
- UA 不在客户端白名单内
- 同一订阅短时间出现多个拉取 IP
- 同一订阅短时间出现多个 UA 类别
- 同一订阅短时间出现多个拉取地区
- 拉取地区和节点上报的用户在线地区不一致

如果订阅来源 IP 命中 `自有节点/可信出口 IP 列表`，泄露保护不会把 IP、地区变化、缺少在线地区证据作为风险分，只保留 UA 等非 IP 信号。

**推荐应急配置**：
```
自动识别自有节点出口 IP: 是
信任节点机器上报 IP: 是
解析节点域名作为可信出口: 是（CF 小云朵域名会自动跳过）
自有节点/可信出口 IP 列表: 手动补充固定出口IP/CIDR，可留空
启用订阅泄露保护模式: 是
泄露保护命中策略: reset_token_uuid
启用泄露保护严格模式: 是
启用泄露保护重复命中升级: 是
泄露保护升级命中次数: 3
泄露保护升级策略: reset_token_uuid
泄露保护触发分数: 80
泄露保护检测窗口: 600
允许拉取IP数: 2
允许UA类别数: 1
允许拉取地区数: 1
```

这样可疑请求会直接触发重置 `token + uuid`，旧订阅和旧节点配置立即失效；用户使用正确客户端重新获取订阅后可恢复。

### 多UA拉取检测
- **启用同订阅多UA检测**: 默认开启，识别同一订阅被多个客户端类别拉取
- **允许的客户端类别数**: 同一订阅 token 在检测窗口内允许出现的客户端类别数
- **检测窗口**: 默认 600 秒
- **处理策略**: 固定为 `reset_token_uuid`；旧值 `observe / throttle / empty / block / reset_token` 会兼容为完整凭据重置

**推荐配置**：保持 `reset_token_uuid`，命中后让旧订阅和旧节点配置一起失效。

### 多地区拉取 / 在线检测
- **同订阅多地区拉取检测**: 默认开启。同一个订阅 token 短时间内从多个地区拉取会触发
- **在线多地区检测**: 默认开启。读取节点已上报的在线 IP 列表，判断同一个用户是否多地区同时在线
- **IP地区缓存时间**: 默认 7 天，避免每次订阅都重复查归属地

归属地优先使用项目内已安装的 `ip2region`（IPv4）。未知地区、内网地址不会参与多地区判断，降低误伤。

### IP限制设置  
- **启用订阅IP限制**: 开启/关闭IP限制功能
- **时间窗口内允许的不同IP数量**: 例如设置为3，表示在时间窗口内最多允许3个不同IP访问
- **时间窗口（秒）**: 例如600秒（10分钟）

**示例场景**：设置为"3个IP，600秒"
- 用户在10分钟内从3个不同IP访问订阅，都可以正常访问
- 第4个不同的IP尝试访问时将被拦截
- 10分钟后，IP记录自动过期，重新计数

### 访问频率限制
- **启用订阅拉取频率限制**: 开启/关闭频率限制
- **时间窗口内允许的最大拉取次数**: 例如10次
- **频率限制时间窗口（秒）**: 例如86400秒（24小时）

**示例场景**：设置为"10次，86400秒"
- 用户在24小时内可以访问订阅10次
- 第11次访问将被拦截
- 使用滑动窗口算法，第一次访问24小时后才会重新计数

### 阅后即焚功能
- **启用阅后即焚功能**: 开启/关闭此功能
- **最大使用次数**: 链接在时间窗口内可被使用的次数，例如1次（真正的一次性）
- **有效时间（秒）**: 时间窗口，例如3600秒（1小时）

**示例场景**：设置为"1次，3600秒"
- 用户访问订阅链接后，立即记录使用次数为1
- 在1小时内，第二次访问时会触发：
  1. ❌ 拦截访问（返回403）
  2. 🔄 **自动重置订阅 token 和节点 uuid**
  3. 📝 旧的订阅链接和旧节点凭据彻底失效
  4. ✅ 用户需要到网站重新获取新的订阅链接
- 1小时后，如果未达到次数上限，计数会自动重置

**使用建议**：
- 设置为 **1次** = 真正的一次性链接，访问后订阅凭证立即重置，必须到网站获取新链接
- 设置为 **3-5次** = 允许多次刷新，适合正常使用，超过次数后重置订阅凭证
- 设置为 **10次以上** = 限制过度频繁访问，超过次数后重置订阅凭证

**重要说明**：
- ⚠️ 达到使用次数上限后，系统会**自动重置用户的订阅 token 和节点 uuid**
- ⚠️ 旧的订阅链接和旧节点凭据将**永久失效**，无法再使用
- ⚠️ 用户需要登录网站，重新获取新的订阅链接
- ✅ 这是最强的安全措施，可以有效防止订阅链接泄露和滥用

## 使用示例

所有功能直接作用于普通订阅链接，无需特殊处理：
```
https://你的域名/api/v1/client/subscribe?token=用户token
```

## 工作原理

### 检查流程
插件在用户访问订阅链接时按以下顺序检查：
1. **客户端行为检测** → 检查UA白名单、同源批量订阅、订阅泄露保护、多UA拉取、多地区拉取、在线多地区
2. **UA重置 / UA黑名单** → 检查User-Agent是否命中重置或黑名单
3. **在线唯一IP阈值** → 检查当前在线唯一IP数是否超限
4. **IP限制** → 检查时间窗口内IP数量是否超限
5. **频率限制** → 检查时间窗口内访问次数是否超限
6. **阅后即焚** → 检查时间窗口内使用次数是否超限

除订阅来源黑名单外，任何一项检查不通过都会统一重置订阅 token 和节点 uuid，并返回 403 提醒用户重新获取订阅。订阅来源黑名单命中时只拒绝订阅请求，不重置凭证。

### 缓存机制
所有数据存储在缓存中，键名格式：
- `subscription_control:last_event:{用户ID}` - 最近一次拦截事件
- `subscription_control:notify_cooldown:{用户ID}:{类型}` - 通知冷却
- `subscription_control:ip_limit:{用户ID}` - IP限制记录
- `subscription_control:rate_limit:{用户ID}` - 频率限制记录  
- `subscription_control:usage:{用户ID}:{token}` - 阅后即焚使用记录
- `subscription_control:risk:ua:{用户ID}:{token_hash}` - 同订阅多UA窗口
- `subscription_control:risk:region:{用户ID}:{token_hash}` - 同订阅多地区窗口
- `subscription_control:risk:source_batch:{ip_hash}:{ua_hash}` - 同源批量订阅窗口
- `subscription_control:risk:leak_ip:{用户ID}:{token_hash}` - 订阅泄露保护拉取 IP 窗口
- `subscription_control:risk:leak_ua:{用户ID}:{token_hash}` - 订阅泄露保护 UA 类别窗口
- `subscription_control:risk:leak_region:{用户ID}:{token_hash}` - 订阅泄露保护拉取地区窗口
- `subscription_control:risk:leak_hit:{用户ID}:{token_hash}` - 订阅泄露保护命中升级窗口
- `subscription_control:ip_region:{ip_hash}` - IP归属地缓存
- `subscription_control:trusted_egress:auto:*` - 自动可信节点出口缓存
- `subscription_control:blocked_count:{日期}` - 每日拦截计数

## 功能详解

### UA黑名单
拦截含有黑名单关键词的User-Agent，例如：
- 爬虫: `spider`, `crawler`, `bot`
- 工具: `wget`, `curl`, `python-requests`
- 测试工具: `postman`, `insomnia`

### IP限制
防止订阅链接被多人共享使用：
- 在时间窗口内，记录不同的访问IP
- 超过设定数量后，新的IP将被拦截
- 已记录的IP可以继续访问
- 时间窗口过期后，IP记录自动清除

### 在线唯一IP阈值
防止用户绕过订阅风控后继续通过二次订阅分发：
- 订阅请求到来时，读取用户当前在线唯一IP数
- 若当前在线唯一IP数大于设定阈值：
  1. 拦截当前访问（返回403）
  2. **自动生成新的订阅token和uuid**
  3. **旧订阅链接与旧节点凭据一起失效**
  4. 用户必须重新获取新的订阅链接
  5. 如启用了通知，会通过邮件 / TG 提醒用户

### 频率限制
防止恶意频繁拉取：
- 在时间窗口内，记录每次访问的时间戳
- 超过设定次数后，将被拦截
- 使用滑动窗口算法，更加精确
- 时间窗口过期后，访问记录自动清除

### 阅后即焚
限制订阅链接的使用次数，并在达到上限后自动重置订阅凭证：
- 在时间窗口内，记录累计使用次数
- 达到设定次数后，会执行以下操作：
  1. 拦截当前访问（返回403）
  2. **自动生成新的订阅 token 和节点 uuid**
  3. **旧的订阅链接和旧节点凭据永久失效**
  4. 用户必须到网站重新获取新链接
- 时间窗口过期后，如果未达到次数上限，使用次数会自动重置

## 典型使用场景

### 场景1：防止订阅链接泄露
```
启用IP限制: 是
IP数量: 2个
时间窗口: 86400秒（24小时）
```
效果：24小时内只允许2个不同IP访问，防止链接被多人使用

### 场景1.2：防止拿到订阅后逐个验活节点
```
启用订阅泄露保护模式: 是
泄露保护命中策略: reset_token_uuid
启用泄露保护严格模式: 是
启用泄露保护重复命中升级: 是
泄露保护触发分数: 80
```
效果：
- 明确恶意 UA 和社交平台预取 UA 会直接拒绝并永久封禁真实来源 IP，不重置用户凭证
- 普通浏览器、空 UA、通用脚本 UA 只拒绝订阅展示，避免误点导致凭证重置
- 旧 Clash、未知客户端、泄露保护高分命中时，重置订阅 token 和节点 uuid
- 拉取地区和用户真实在线地区不一致时，风险分会升高
- 同一订阅被多个 IP、多个 UA、多个地区短时间拉取时，直接进入保护模式
- 旧订阅链接和旧节点配置立即失效，无法继续低流量验活节点

### 场景1.3：同一来源批量拉取多个用户订阅
```
自有节点/可信出口 IP 列表: 填写你的所有节点出口IP/CIDR
启用同源批量订阅检测: 是
同源批量用户阈值: 3
同源批量检测窗口: 600
同源批量命中策略: reset_token_uuid
```
效果：
- 同一真实客户端 IP + 同一 UA 类别短时间访问 3 个用户订阅时，当前请求进入保护
- 默认重置订阅 token 和节点 uuid，不向批量来源保留可继续验活的旧配置
- 自有节点出口 IP 会被排除，用户开着你的节点更新订阅不会误触发
- 历史动作会统一按 `reset_token_uuid` 处理，不再保留空订阅、限速或单纯拦截分支

### 场景1.4：禁止国内云厂商来源拉取订阅
```
启用订阅来源 IP 黑名单: 是
订阅来源 ASN 黑名单: AS135377, AS59077, AS45102, AS37963, AS134963, AS24429, AS45090, AS133478, AS132203, AS136907, AS55990, AS131444
订阅来源组织关键词黑名单: ucloud, aliyun, alibaba, tencent, huawei cloud, huaweicloud
订阅来源黑名单命中策略: block
```
效果：
- 来自 UCloud、阿里云、腾讯云、华为云等 ASN 或组织名匹配的订阅请求会直接返回 403
- 不重置用户订阅 token 和节点 uuid，避免只因云厂商来源请求就影响正常用户凭证
- 自有节点/可信出口 IP 会被排除，避免用户开着你的节点更新订阅被误拦

### 场景1.5：用户做二次订阅后继续分发
```
启用在线唯一IP数阈值: 是
在线唯一IP数阈值: 12
```
效果：
- 即使对方只拉过一次你的原始订阅，并自行做了镜像订阅
- 只要该账号实际在线唯一IP数超过12
- 就会自动重置 `token + uuid`，旧凭据整体失效

### 场景2：真正的一次性订阅（阅后即焚）
```
启用阅后即焚: 是
使用次数: 1次
有效时间: 3600秒（1小时）
```
效果：
- 第1次访问：✅ 成功，记录使用次数
- 第2次访问（1小时内）：
  - ❌ 被拦截（403错误）
  - 🔄 **自动重置订阅token**
  - 📝 旧链接永久失效
  - 用户需要登录网站获取新链接
- 1小时后（如果只访问了1次）：计数重置，可以继续使用

### 场景3：限制爬虫扫描
```
启用UA黑名单: 是
黑名单内容:
  bot
  crawler
  python
  wget
  curl
```
效果：拦截常见爬虫和工具的访问

### 场景4：防止频繁拉取
```
启用频率限制: 是
拉取次数: 30次
时间窗口: 3600秒（1小时）
```
效果：1小时内最多拉取30次，防止过度频繁请求

## 故障排除

### 插件未生效
- 确认插件已在管理面板中启用
- 检查相关功能开关是否打开
- 查看 `storage/logs/laravel.log` 中的日志

### 阅后即焚不生效
- 确认"启用阅后即焚功能"已开启
- 检查"最大使用次数"和"有效时间"的设置
- 查看日志确认是否有"订阅使用计数"记录
- 如果使用文件缓存，尝试清空缓存后重试

### IP限制不准确
订阅如果经过 Cloudflare / v2node 订阅反代，页面会区分：

- `真实客户端 IP`：用于订阅 IP 限制、多地区拉取等风控判断。
- `代理入口 IP`：例如 Cloudflare 边缘 IP 或本机 Nginx 反代 IP，只用于排查链路。
- `IP 来源`：表示真实客户端 IP 来自 `CF-Connecting-IP`、`True-Client-IP`、`X-Forwarded-For`、`X-Real-IP` 还是 `REMOTE_ADDR`。

只有请求来源 IP 命中 `可信代理 CIDR 列表` 时，插件才会信任这些真实 IP 头，避免外部直接伪造 `CF-Connecting-IP`。

确保Nginx/Apache正确配置，传递真实IP：

**Nginx配置示例：**
```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

**Cloudflare用户：**
插件会优先识别 `CF-Connecting-IP` / `True-Client-IP`，并内置 Cloudflare 官方 IPv4/IPv6 CIDR 列表。若 Cloudflare 更新 IP 段，应同步更新插件配置中的 `可信代理 CIDR 列表`。

### 误拦截正常用户
- 检查UA黑名单是否设置过于宽泛
- 适当增加IP限制数量和时间窗口
- 适当增加频率限制和阅后即焚的阈值
- 检查日志确认具体拦截原因

## 性能优化建议

1. **使用Redis缓存**
```env
CACHE_DRIVER=redis
```

2. **合理设置时间窗口**
- IP限制时间窗口：建议10-30分钟
- 频率限制时间窗口：建议1-24小时
- 阅后即焚有效期：建议5-60分钟

3. **合理设置限制值**
- 在线唯一IP阈值：建议10-20个（用于识别明显异常扩散）
- IP数量：2-5个（根据用户使用习惯）
- 频率次数：10-50次（根据客户端更新频率）
- 阅后即焚次数：1-10次（1次最严格）

## 技术特点

- 🚀 **无需新增表** - 运行状态完全基于缓存，自动可信出口只读取现有节点/机器数据

- ⚡ **高性能** - 缓存操作，对订阅速度影响极小
- 🔒 **安全可靠** - 多层防护，有效防止滥用
- 📝 **详细日志** - 记录所有拦截和使用信息
- 🛠️ **易于调试** - 日志清晰，问题易排查
