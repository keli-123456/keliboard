# PayTaro 支付接入

本插件默认通过 PayTaro 官方显码 API 创建订单，在我们自己的 keli-user 支付弹窗中展示二维码、金额和收款地址。付款后仍由异步通知触发 KeliBoard 原有订单处理。PayTaro 收银台跳转保留为可选兼容模式。

**站内模式需要同时更新 KeliBoard 插件和新版 keli-user 主题包。keli-admin 不需要改动或重新构建。旧主题未更新时，请先选兼容模式，避免缺少手机唤起和过期处理。**

## 开通与配置

1. 在 PayTaro 商户后台创建应用，确认原始订单币种为 **CNY**，开通需要的支付渠道，取得同一应用的 **App ID** 和 **App Secret**。
2. 更新包含本插件的 KeliBoard 后，在管理员的**插件管理**中安装并启用 **PayTaro**。插件不会自动开启，也不会替换现有支付方式。
3. 在**支付配置**中添加支付方式，接口选择 **PayTaro**，填写显示名称、App ID、App Secret，展示方式选择**站内支付弹窗**。
4. 从 PayTaro 商户后台的**应用管理 → 付款方式**复制所需渠道的 UUID，填写到**支付渠道 UUID**。该渠道必须已开通且打开“展示”。例如，支付宝和 USDT-TRC20 分别添加两条 PayTaro 支付方式，各填自己的渠道 UUID；不要填写应用 UUID 或订单 UUID。
5. 按需设置面板手续费与 HTTPS 回调域名，保存并启用。PayTaro 渠道可能另外收取费用，付款弹窗显示网关返回的实际应付金额，到账核对仍使用原始人民币订单金额。
6. 代理自有支付可在代理中心的支付设置中选择 PayTaro，填写自己的应用和渠道信息。仍受原有支付归属、站点授权和订单校验约束。

不要填写易支付 PID、MD5 密钥或其他 AI API Key。网关固定使用 `https://v3.paytaro.com`，无须填写 API 地址。切换到**跳转 PayTaro 收银台（兼容模式）**时不需要渠道 UUID。

## 站内付款体验

- 支付宝：本地生成二维码，不嵌入 PayTaro 页面。手机点击“前往支付宝付款”唤起支付宝或进入支付宝官方付款页面；不会进入 PayTaro 收银台。微信和 QQ 内置浏览器会提示使用系统浏览器。
- 加密货币：显示收款地址、网络与精确应付数量，提供复制按钮。必须按显示的网络和数量支付，过期后不应继续转账。
- 长支付宝链接采用低纠错、大尺寸二维码，不叠加 Logo，签名编码原样保留。
- 倒计时依据网关剩余秒数，不依赖手机与服务器时钟一致。过期后隐藏付款码并停用继续付款与复制操作。
- 页面只轮询本面板已有的订单状态接口；PayTaro 密钥和 API 请求留在服务器端。弹窗等待期间持续检查，隐藏页面时暂停；过期后另留两分钟检查迟到的到账通知。“我已支付”仅进入订单确认页，不会直接修改订单状态。

App Secret 同时用于下单认证与回调认证，只应存放于受保护的支付配置中，不应放到主题、浏览器脚本、网址或工单里。重置密钥前应处理旧应用尚未完成的订单；新旧密钥不一致会导致旧通知被拒绝。

## 回调与站点回跳

- 下单时自动发送当前支付配置对应的回调地址：`https://回调域名/api/v1/guest/payment/notify/PayTaro/支付方式UUID`。无需手工编造 UUID，也无需新增路由。
- **回调必须使用 HTTPS**，域名需公网可达并路由到本面板。若站点前面有反向代理而自动生成了 HTTP 地址，请在该支付方式的回调域名中明确填写 HTTPS 域名。
- Nginx、CDN、WAF 应允许该回调路径的 POST JSON 请求，并透传 `X-App-Secret` 请求头；不能给该接口加浏览器验证码、登录跳转或缓存。不要为了接入关闭全站防护。
- 返回地址沿用 KeliBoard 根据订单站点生成的地址，保留 `/#/pay-success?trade_no=...`，不会统一回到主站。
- 站内弹窗在本面板确认订单完成后进入支付成功页。兼容模式中 PayTaro 的“返回商户网站”由用户点击触发，不是自动回跳。页面跳转本身不代表到账。

## 到账验证

- 仅接受 POST JSON，使用常数时间比较验证请求头中的 App Secret，并匹配 App ID。
- 仅 `PAID`、`SUCCESS` 会进入到账流程，兼容商户后台手动重发通知。
- 按 `order_currency=CNY` 和原始 `order_amount` 核对金额，不使用加密货币的 `pay_amount`；金额必须精确到分，包含面板已计算的手续费。
- PayTaro `merchant_no` 对应面板订单号；面板的支付流水号保存 PayTaro `transaction_no`。渠道的 `callback_no` 不是本插件保存的流水号。
- 使用原有支付方式归属、金额检查和订单幂等处理。验收通过后返回 `success`；认证、金额或处理失败返回非 200，让 PayTaro 重试。重复通知不会重复充值或重复开通。
- 下单保留 TLS 证书验证，限制连接及请求时长，不跟随携带密钥的重定向、不自动重试创建订单。错误提示不会透传上游响应正文或密钥。

## 上线验收

本地回归使用模拟网关和内存数据库，不访问真实支付 API 或生产数据库：

```sh
php vendor/bin/phpunit tests/Unit/Plugins/PaytaroTest.php
php vendor/bin/phpunit tests/Unit/Plugins/PaytaroInlineTest.php
php vendor/bin/phpunit tests/Unit/Services/PaymentOrderRegressionTest.php
```

商户配置完成后，先用允许测试的小额订单逐项核对，再向用户开放：

1. 创建订单，确认站内弹窗显示正确渠道、实际应付金额和有效倒计时；实际应付金额可能包含 PayTaro 渠道费用。原始订单金额须等于面板订单加面板手续费。
2. 真实付款后确认订单已完成，套餐或余额到账正确。
3. 在 PayTaro 商户后台的交易管理中重发通知，确认得到成功响应且不会重复到账。
4. 从代理/分站下单，确认返回原站点、使用正确商户应用。
5. 支付失败、未支付和超时订单不能被当成已支付；通知失败先检查 HTTPS、应用密钥、回调路径和 WAF。
6. 用桌面扫描支付宝二维码、用手机唤起支付宝，分别检查付款与到账；使用加密货币时另外验证网络、复制地址和精确数量。

## 当前范围

此版本包含站内显码及收银台兼容模式，不包含主动查单补单或自动退款。站内状态以本面板订单表为准，不新增公开 PayTaro 订单查询代理或 UUID 持久化字段。通知故障可先查明原因，再从商户后台重发通知；不要以页面跳转或截图手工判定成功。

参考：[PayTaro 官方完整文档](https://v3.paytaro.com/llms-full.txt)、[自定义显码接入](https://v3.paytaro.com/#/docs/custom-qr)、[支付回调与验签](https://v3.paytaro.com/#/docs/api-notify)。
